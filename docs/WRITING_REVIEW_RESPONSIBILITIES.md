# 2번: 기준별 코드 검사·에이전트 검사 책임 분리

대상: [작성·평가 기준표의 기존 33개 항목](NPU_WRITING_RUBRIC.md). 새 기준은 추가하지 않는다.

연구 내용은 **우리 CUDA 연구 근거**다. NPU 논문은 구조·설명·비교 방식의 참고 자료다.

이 문서와 [책임 명세 JSON](../evaluation/writing/npu-review-responsibilities.v1.json)은 **누가 무엇을 판단하는지**를 확정한다. 이번 작업에서는 근거를 장·절에 배정하거나 입력 문맥을 조립하지 않았으며, 생성·검토·수정 호출도 변경하지 않았다. 이것들은 3번 이후의 작업이다.

## 판정 원칙

- **코드 최종 판정 6개:** C01~C06. 정확한 구조·식별자·참조·배치를 판정한다. 이런 오류를 모델에게 다시 판단시키지 않는다.
- **책임을 나눠 판정하는 2개:** C07~C08. 수치·메타데이터의 명확한 일치는 코드, 범위·귀속·본문 표현의 의미는 에이전트가 맡는다.
- **에이전트 의미 판정 25개:** I01~F02. 코드로 ID·필드·산술 등을 먼저 확인할 수 있지만, 그 통과가 내용 충족을 의미하지 않는다.
- 모델의 `met`이 명백한 코드 오류를 덮어쓸 수 없다. 구현하지 않은 코드 검사를 통과했다고 표시하지 않는다.
- 불명확한 실험 조건·단위·출처는 `needs_check`다. 모델이 그럴듯한 값을 만들어 해소하지 않는다.

## A. 코드가 최종 판정하는 기준

| ID | 코드의 책임 | 에이전트의 책임 | 판정 경계 |
|---|---|---|---|
| C01 | 제목·순서·본문 칸이 계획과 정확히 일치하는지 검사 | 이 기준의 재판정 없음 | 논리 전개와 가독성은 별도 의미 기준 |
| C02 | 근거 표기가 있고 사용 ID가 해당 장의 허용 목록에 있는지 검사 | 이 기준의 재판정 없음 | ID가 맞아도 모든 주장이 근거를 가졌거나 인용이 적절하다는 뜻은 아님 |
| C03 | 계획 ID·참조·의존 순서·역할 식별자의 유효성 검사 | 이 기준의 재판정 없음 | 유효한 계획 객체가 의미적으로 좋은 실험 설계라는 뜻은 아님 |
| C04 | 표 근거 ID·행열 구조·중복 배치를 검사하고 표를 코드로 렌더링 | 표 구조를 재판정하지 않음 | 셀 값의 충실성은 C07, 비교 조건·해석은 E11 등에서 판단 |
| C05 | 필수 항목이 실제 선택한 가이드의 기준 ID에 연결됐는지 검사 | 연결 ID의 유효성을 재판정하지 않음 | 실제 작성에 그 기준이 반영됐는지는 별도 의미 판단 |
| C06 | 실제 본문 문단 ID·장 소속·필수 항목 검토의 누락/중복 검사 | 문단 존재 여부를 재판정하지 않음 | 존재하는 문단을 인용했다고 기준을 충족하는 것은 아님 |

이 범위의 기존 구현은 `compose_parts`, `validate_body`, `normalize_research`, `validate_plan`, `render_paper`, `materialize_review`, `validate_review`에 있다. **기존 검사 기능의 존재와 새 33개 기준표 실행기의 연결 완료는 다르다.**

## B. 하나의 기준 안에서 책임을 나눠야 하는 항목

| ID | 코드가 판단할 부분 | 에이전트가 판단할 부분 | 최종 처리 원칙 |
|---|---|---|---|
| C07 | 명시적으로 연결한 수치·단위·통계량의 일치, 동일 범위·분해 관계가 선언된 합계/비율 | 측정 구간·조건·통계량의 의미가 같은지, 소수 쉼표 등의 모호성을 원문에서 해소할 수 있는지 | 명확한 계산 모순은 코드 실패. 범위가 불명확하면 계산하지 않고 보류. 모델의 의미 판정만으로 모순을 덮거나 값을 자동 수정하지 않음 |
| C08 | `writing_role`, `claim_status`, `source_origin` 등 원래 메타데이터 유지 여부 | 문장이 계획·가설·작성자 해석·AI 조언을 실제 측정 성과로 격상하지 않았는지 | 메타데이터와 본문 의미가 모두 맞아야 충족. 필드 전달 성공만으로 승인하지 않음 |

예를 들어 `131.248s`와 `131248s`의 수치 불일치는 같은 측정 대상으로 명시적으로 연결되었다면 코드가 검출할 수 있다. 반면 두 값이 같은 측정 구간을 가리키는지 불분명한 상태에서 값만 보고 하나를 정답으로 고르는 것은 코드 책임이 아니다. 원문 검토로도 결정할 수 없으면 저자 확인으로 남긴다.

## C. 에이전트가 의미를 판정하는 기준

아래 코드 업무는 **사전 검사**다. 필드가 없거나 참조가 틀렸다는 사실은 코드로 검출할 수 있지만, 필드가 채워졌다는 이유로 해당 의미 기준을 통과시키지 않는다.

| ID | 코드가 확인할 부분 | 에이전트가 최종 판단할 부분 | 자동 판정하면 안 되는 것 |
|---|---|---|---|
| I01 | 배경·병목 근거와 인용 문단 ID | 중요성→문제→연구 초점의 연결과 신규성 과장 여부 | 배경·문제라는 단어의 존재 |
| I02 | 선언된 비교 구성·측정 범위 필드와 참조 | CPU/GPU·부분/전체 비교 범위를 정확히 예고하는지 | 같은 단위면 같은 범위라는 가정 |
| I03 | 기여·질문·근거·결과 절의 연결 ID | 기여와 결과 요약이 실제 연구 범위에 한정되는지 | 골든 논문과 같은 기여·RQ 개수 |
| R01 | 문헌 ID·서지 레코드·제공된 문헌 근거 연결 | 문헌의 실제 뒷받침과 주제별 비교의 적절성 | 서지 레코드가 있으면 내용도 맞다는 가정 |
| R02 | 문헌·연구 근거 ID | 선행연구와 차이·신규성 표현이 조사 범위를 넘는지 | 인용 수·단어 차이로 차별성 인정 |
| D00 | 설계·비교 구성·질문의 선언된 연결 | 설계가 질문에 답할 수 있고 실험 분기를 잘못 합치지 않는지 | 계획 참조가 유효하면 설계도 타당하다는 가정 |
| D11 | 측정 시작/끝·포함/제외 필드와 근거 참조 | 본문과 원문의 실제 실행 경로·측정 경계 일치 | 필드가 채워졌으면 범위가 맞다는 가정 |
| D12 | 명시된 예열·반복·동기화·통계량 필드와 수치 | 실제 절차·최저/평균·미확인 조건을 정확히 설명하는지 | 일반적인 관행으로 누락 절차 채우기 |
| D21 | 기준선·버전·변경점 필드와 근거 참조 | 무엇이 실제로 고정/변경됐고 비교가 통제됐는지 | 같은 버전명·Same 표기만으로 동일 조건 인정 |
| D22 | 명시한 변경 구성과 근거 참조 | 복합 변경을 단일 요인의 인과 효과로 과장하는지 | 기록된 변경 필드 수로 원인 수 확정 |
| D31 | 입력·워크로드·검증 지표 필드와 수치 연결 | 단일/전체 입력 및 정확성 검증 범위의 설명이 적절한지 | 데이터 수·지표 이름이 있으면 검증 충분으로 인정 |
| D41 | 구현·실험·계획 ID와 성격 메타데이터 | 적용 위치·범위, 구현 완료와 제안/계획의 구분 | 최적화 명칭이 있으면 구현 완료로 인정 |
| D51 | 제공된 장치·OS·버전 필드와 근거 참조 | 실제 환경과 일치하고 재현 정보·미확인을 충분히 밝히는지 | 그럴듯한 버전 문자열을 실제 환경으로 인정 |
| D52 | 선언된 환경 식별자 차이·누락 및 수치 연결 | 환경 차이의 비교 영향과 한정 표현의 적절성 | 문자열이 같으면 교란 요인도 없다는 가정 |
| E00 | 질문·결과 절·표 ID와 구조 | 결과 안내가 질문·지표·표 역할을 이해하게 하는지 | 표·RQ 개수를 맞추면 글이 적절하다는 판단 |
| E11 | 근거·수치·단위·질문 ID의 명시적 연결 | 질문의 답, 조건·범위의 적절성, 성능과 정확성의 구분 | 수치가 맞으면 비교도 타당하다는 판단 |
| E12 | 인용한 예외·실패 근거 ID와 상태 | 중요한 반례·실패·상충이 빠지거나 축소됐는지 | 실패 키워드나 예외 개수로 보존 인정 |
| E21 | 선언된 부분/전체 구간과 수치·계산 관계 | 부분 성능을 전체 서비스 성능·실시간성으로 확장하는지 | 같은 단위의 두 값만으로 부분/전체 관계 추론 |
| E22 | 동일 범위라고 선언된 순위·가속비 산술과 조건 누락 | 조건 동등성, 제외 사유, 워크로드별 예외의 적절성 | 산술이 맞으면 비교 의미도 맞다는 판단 |
| E31 | 명시된 전후 기준선·구성·수치·범위 연결 | 추가 이득의 해석과 별도 분기/누적 개선의 구분 | 버전 번호 순서를 누적 개선의 증거로 인정 |
| E32 | 원인 설명의 근거 ID와 관측/해석 메타데이터 | 관측·원인 가설·AI 조언의 귀속과 인과 미분리 | 숫자 일치·supported 플래그로 인과 승인 |
| L01 | 명시한 범위·환경·불확실성 항목과 근거 참조 | 구체적인 교란 요인·재현성 한계·주장 범위의 적절성 | 한계 제목·일반적인 한계 문장만으로 충족 인정 |
| L02 | 검증 상태·미측정·미해결 메타데이터 유지 | 미검증 항목이 실제 주장을 제한하도록 설명됐는지 | 측정 부재를 검증 성공이나 적용 제외로 해석 |
| F01 | 결론에서 연결한 본문 주장·근거·수치 ID의 존재·일치 | 본문보다 새롭거나 강한 주장·인과·보증을 추가했는지 | 같은 단어·수치가 본문에 있으면 과장도 없다는 가정 |
| F02 | 후속 과제와 연결한 한계 ID와 상태 | 실제 앞선 한계에서 이어지고 미수행으로 표현되는지 | 한계 ID만 연결하면 후속 과제가 적절하다는 판단 |

## 기존 코드와 아직 없는 검사 구분

| 코드 검사 묶음 | 현재 상태 | 담당 범위 |
|---|---|---|
| `structure`, `evidence_ids`, `plan_links`, `tables`, `guideline_ids`, `review_links` | 기존 기능 있음 | 구조·ID·배치·참조 무결성. 의미 판단은 아님 |
| `provenance` | 일부 있음 | 메타데이터 전달이 중심. 완전한 보존 검사로 볼 수 없음 |
| `numeric_tuples` | 추가 구현 필요 | 연결된 수치·단위·통계량 및 선언된 계산 관계 |
| `literature_ids` | 추가 구현 필요 | 문헌 ID·서지·제공된 근거의 연결 |
| `declared_fields` | 추가 구현 필요 | 계획에 선언한 측정·환경·입력 필드와 참조 |
| `question_links` | 추가 구현 필요 | 선언된 연구 질문과 결과 절·필수 항목 ID 연결 |
| `body_claim_links` | 추가 구현 필요 | 결론의 본문 주장·근거·수치 참조 |

이는 구현 상태를 구분한 표다. 새 검사기를 이번 단계에서 구현했다거나 모든 항목이 현재 앱에서 실행된다는 뜻이 아니다. 자유 문장에서 의미를 추출해야만 검사할 수 있는 부분을 이미 결정적인 코드 검사인 것처럼 취급하지 않는다.

## 판정 결과의 책임

- 코드 결과: `pass / fail / needs_check`. 규칙 ID, 실패 위치, 이유를 기록하는 책임을 가진다.
- 에이전트 결과: `met / partial / missing / needs_check / not_applicable`. 기준 ID, 실제 문단 ID, 관련 근거 ID와 판단 이유를 제시하는 책임을 가진다.
- 에이전트가 반환한 ID가 실제 존재하는지는 코드가 확인하고, 그 인용이 기준을 뒷받침하는지는 에이전트가 판단한다.
- `not_applicable`의 연구 범위상 타당성은 에이전트가 판단한다. 근거가 없는데 성과를 주장한 경우에는 `needs_check`다.
- 최종 결과 집계는 코드 책임이다. 코드 오류를 에이전트 승인으로 덮거나 중요 의미 기준의 보류를 완료 승인으로 바꾸지 않도록 해야 한다. 이 집계 로직의 실행 경로 연결은 이번 작업에 포함하지 않았다.

## 이번 단계의 완료 범위

2번 작업에서는 33개 기준 모두의 코드 책임·에이전트 책임·최종 판정 담당·오판 방지 경계를 문서와 JSON에 대응시켰다. 입력 문맥 구성과 생성 흐름은 그 단계에서 변경하지 않았다. 이후 사용자가 요청한 3번의 진행 범위는 [입력 문맥 구성 문서](WRITING_INPUT_CONTEXT.md)와 최신 HANDOFF에 별도로 기록한다. 4~6번의 생성·의미 검토·수정 루프 개편이나 실제 논문 품질 평가를 완료했다는 뜻은 아니다.
