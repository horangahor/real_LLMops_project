# 결과 장 1개 실제 생성·검토 시험 (2026-10-31)

실제 CUDA 근거 4개로 결과 장 하나를 생성했다. **최종 판정은 미통과**다. 모델은 세 소절을 모두 `parts.p0`에 쓰고 `p1`, `p2`를 비웠다. 코드가 이를 차단했지만, 진단 목적으로 수행한 의미 검토는 필수 항목 4개를 모두 충족으로 판정했다. 내용 충족과 소절 배정 준수는 별도로 검사해야 한다.

## 범위와 산출물

- 연구 근거: 기존 v3 스냅샷의 58쪽 표에서 선택한 `P0058F0006`~`P0058F0009`. sparse.py/CUDA의 forward·backward bound 시간, bound 가속비, 추론+bound+검증 범위의 가속비다. 원문 표와 대조한 제한된 시험이며 전체 추출의 정확도 검증은 아니다.
- 참고 지침: SHA256으로 NPU 프로파일 하나만 선택한 `ref1_evaluation`. 질문별 답 제시, 측정 범위 구분, 해석 한계 서술만 참고했다. 연구 주제는 CUDA다.
- 계획: 코드로 정한 세 소절과 필수 항목 네 개. 전체 논문을 대상으로 계획 모델을 호출하지 않았다. 새 33개 기준표 전체가 실행기에 연결됐다는 뜻도 아니다.
- 실제 호출: `solar-pro4-260806`으로 생성 1회 + medium 추론 의미 검토 1회. 원래 실행의 생성·검토 합계는 54.26초였다. 이 작은 표본으로 전체 논문 소요 시간이나 기존 대비 개선율을 예측하지 않는다.
- API 보고 토큰: 생성 6,156개(입력 5,482 / 출력 674), 검토 11,439개(입력 6,644 / 출력 4,795, 출력 중 reasoning 4,234). 합계 17,595개다. 금액은 산정하지 않았다.

## 실제 관찰

| 대상 | 관찰 | 의미 |
|---|---|---|
| JSON | 파싱 가능하며 p0/p1/p2 키가 있음 | 스키마만으로 빈 소절과 잘못된 배치를 막지 못했다. |
| 본문 형식 | p0에 소제목 세 개와 전체 본문, p1/p2는 빈 문자열 | 기존 `compose_parts`가 거부했다. 정상 장으로 채택할 수 없다. |
| 소절 배정 | p0에 p1용 `P0058F0009`까지 포함 | 장 허용 ID 검사만으로는 놓친다. 소절별 허용 목록 검사가 필요하다. |
| 필수 내용 | 의미 검토는 4/4 met, 가이드 1/1 applied | 계획한 네 항목에 대한 모델 판정이다. 논문 품질 100%나 전체 골든 기준 충족을 뜻하지 않는다. |
| 측정 범위 | bound 약 5.3배와 추론+bound+검증 4.86~4.89배를 구분 | 이번 후보에서는 범위 구분을 유지했다. 다른 장까지 일반화할 수 없다. |
| 사실 혼입 | 후보에서 NPU 장치·벤더·실험 수치 혼입은 발견하지 못함 | 구조와 CUDA 연구 사실의 분리가 이 사례에서는 유지됐다. |
| 원인 해석 | p4는 배율 차이를 “bound 계산 외의 요소가 포함되면서 … 이득이 … 줄어들 수 있음을 보여준다”로 설명 | 표는 수치 차이를 보여주지만 구성 요소별 시간이나 원인을 분리한 실험은 주어지지 않았다. |
| 검토 심각도 | 위 해석을 warning으로 기록하고 `approved=true` | 지침은 근거 없는 해석을 error로 요구한다. 실제 판정은 완곡한 표현에 관대했다. |

`results_pilot_p2/p4/p6`는 각각 1.1/1.2/1.3의 본문 ID다. 빈 줄 단위 인덱싱에서 제목을 제외해 번호가 건너뛴다. 현재 문단 ID에는 parts 출처가 없어, 합쳐진 본문만 검토하면 배치 오류가 가려진다.

수동 검토에서는 p4를 “표에서 결합 범위의 가속비가 bound 단독 범위보다 낮게 기록되었다. 제공된 기록만으로 그 원인을 분리해 확인할 수는 없다.” 정도로 제한하는 것이 적절하다고 판단했다. 이는 수정 제안이며 후보를 실제 수정하거나 재승인하지 않았다.

## 우선 추가할 장별 의미 검토

1. **주장 종류 구분:** 관측, 계산으로 도출한 값, 가설, 인과 설명을 구분하고 근거가 허용하는 수준을 판정한다. “수 있다”라는 표현만으로 근거 없는 원인 설명을 경고로 낮추지 않는다.
2. **위치와 의미 확인:** 필수 항목의 설명·연결 기준·배정 소절·실제 문단·근거를 함께 받는다. 장 어딘가에 관련 단어와 수치가 있다는 이유만으로 met을 주지 않는다.
3. **조건과 일반화 검토:** n=5, forward/backward, bound 단독/결합 범위를 보존했는지, 미확인 환경·정확성·실시간성까지 성과를 확장했는지 확인한다.
4. **논문 서술 검토:** “혼동하지 않아야 한다” 같은 독자 지시·방어적 반복을 결과 서술로 다듬을 필요가 있는지 판단한다. 문체·문맥 판단은 에이전트 책임이다.

코드 통과 후 해당 장의 근거·기준·문단으로 의미를 검토한다. 모델에는 코드가 확정한 오류를 다시 판정시키지 않는다. 이번 시험만 실패 형태와 판정 차이를 보기 위해 코드 미통과 후보도 진단 검토했다.

## 다음 순서와 검증 범위

소절별 코드 검사를 최초 생성·캐시에 공통 적용하고 문단의 part 출처를 보존한다. 다음으로 장별 의미 검토에 주장 판정·심각도 정책을 연결한 뒤 미달 문단만 고치는 제한된 루프를 연결한다. 서비스의 전체 검토·편집 흐름을 이번 시험으로 교체하지 않았다.

시험 도구는 기본 준비만 수행한다. `--generate`는 외부 호출을 허용하고, `--replay`는 입력 해시가 일치하는 기존 캐시만 읽으며 없으면 실패한다. 현재 PC에서 추가 API 호출 없이 재검사하려면:

```powershell
.\.venv\Scripts\python.exe -B -X utf8 evaluation/writing/run_chapter_pilot.py --replay
```

전체 연구 근거의 미해결 40개와 `ready_for_drafting=false`는 유지했다. 기존 서비스 초안·latest 포인터도 갱신하지 않았다. 자동 부분 수정과 재검토는 실행하지 않았다.

자동 코드 테스트 216개 통과. 새 3개는 실제 실패 형태, 장 허용 ID가 소절 배정을 위반하는 경우, 코드와 의미 판정의 결합을 검증한다. sandbox 임시 폴더의 Windows 긴 경로 권한 문제로 첫 전체 실행이 실패해, 해당 검사 프로세스의 TEMP/TMP를 워크스페이스 `tmp/chapter-pilot-tests`로 지정한 뒤 전부 통과했다. 시스템 환경 설정은 바꾸지 않았다.
