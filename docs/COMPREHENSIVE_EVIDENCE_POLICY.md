# 기존 전체 수집 모드의 작성 게이트와 숫자 검사

2026-11-03 구현. 식별자: `comprehensive-gate-v1`, `comprehensive-decimal-comma-v1`.

PR #1(`docs/WORKFLOW2_EVIDENCE_APPROACH.md`) 제안 중 API 호출 없이 할 수 있는 부분을 **기존 전체 수집 모드에만** 적용했다.

- 0단계: 측정
- 1단계: 게이트 정책
- 3단계: 숫자 검사

질문 기반 근거 수집 모드(`requirement_*.py`)는 바꾸지 않았다. 두 모드가 함께 쓰는 함수(`writing_eligible`, `verify_page`, `ground`, `structure_markdown_tables`)도 동작을 바꾸지 않았다. 새 규칙은 별도 모듈 `comprehensive_policy.py`에 두고, 전체 수집 경로에서만 호출한다. 질문 기반 모듈이 이 모듈을 쓰지 않는다는 것은 `tests/test_comprehensive_policy.py`의 격리 테스트가 검사한다.

## 바뀐 것

### 작성 게이트: 막음과 경고를 나눈다

이전에는 `completion.unresolved_source_items`가 1개만 있어도 `ready_for_drafting=false`였다. 이제 각 항목을 원문 요소와 대장 기록으로 분류한다.

| 분류 | 처리 | 판정 기준(코드) |
|---|---|---|
| `missing_content` 내용 누락 | **막음** | 아래 경고 조건에 해당하지 않는 대장 미해결 |
| `response_failure` 모델 응답 실패 | **막음** | 빈 JSON·대장 행 검증 실패·재검토 미완료 |
| `source_unavailable`, `unreviewed`, `other` | **막음** | 원문 아카이브 없음, 미검토 요소, 분류할 수 없는 항목 |
| `non_research` 구분선·제목·연결 문장 | 경고 | 원문이 구분선이거나, 수치·단위·`라벨: 값`이 없는 짧은 요소(제목 60자, 그 외 20자 이하, 공백 제외) |
| `acronym_only` 약어 표기만 다름 | 경고 | 작성용 사실이 연결되어 있고, 보존 검사 결과가 대문자 약어 누락뿐 |
| `reread_duplicate` 재판독 중복 | 경고 | `review:`/`enh:`/`img` 재판독본이 같은 쪽의 원 요소와 같은 글이고, 원 요소가 보존(또는 경고로 정리)됐으며, 재판독본의 모든 수치가 원 요소나 작성용 사실에 있음 |
| `unreadable_image` | 경고 | 판독 불가 이미지 |
| `quarantined_fact` | 경고 | 검증에서 작성 입력에서 빠진 후보 |
| `human_accepted` | 경고 | 사람이 이유를 적고 진행을 허용한 막음 항목 |

- `ready_for_drafting`은 작성용 근거가 있고, 84쪽을 모두 검토했으며, 막음 항목이 0일 때만 `true`다.
- 원래 `unresolved_source_items`는 지우지 않는다. 분류 결과는 `completion.gate`, `blocking_source_items`, `warning_source_items`에 따로 둔다.
- 원문 아카이브를 읽지 못하면 대장 항목을 모두 막음으로 둔다.
- 경고는 버리는 것이 아니다. 화면의 "경고 항목"에 그대로 남아 검토할 수 있다.

### 사람이 막음 항목의 진행을 허용

근거 화면의 "작성을 막는 항목" 아래에서 항목과 허용 이유를 골라 **확인 완료: 작성 진행 허용**을 누른다.

- 기록은 실행 폴더의 `human-gate-decisions.json`에 쌓인다. 재추출해도 같은 기록을 다시 읽는다.
- 허용은 **항목 문구 전체**에 묶인다. 재추출로 항목 내용이 바뀌면 다시 막음이 된다.
- 이유 없이는 저장하지 않는다. 지금 막음 목록에 없는 항목도 거부한다.

### 소수 쉼표 숫자 검사

OCR이 소수점을 쉼표로 읽은 값(`131,248s`)을 천 단위(`131248s`)로 정규화한 측정값을 찾는다. 판정 근거는 같은 원문 요소 안에서만 찾는다.

- 천 단위로 읽은 값이 같은 요소의 `total elapsed`보다 크다.
- 또는 소수로 읽은 값이 괄호 안 비율(%)과 total 대비 일치한다.

해당 사실에는 `numeric_issues`를 추가해 작성 입력에서 뺀다. **값 자체는 고치지 않는다.** 사람 사실 검토로 바로잡으면 다시 표시하지 않는다. `1,168 samples/s`처럼 단위가 다르거나, total·비율로 확인되지 않는 쉼표 값은 건드리지 않는다.

### 적용 지점

`research_extract_v3.apply_policy`가 아래 지점에서 실행된다. 모델을 호출하지 않는다.

- 전체 추출 종료
- 저장본 불러오기(`load_saved_evidence`)
- 사람 제외·사실/측정 승인·중복 결정·미확인 복구·중복 확인 후 저장

## 11/2 저장본에 적용한 결과

`python -X utf8 -B evaluation/extraction/comprehensive/policy_report.py`. 이관 ZIP에서 직접 읽으며 아무것도 복원하거나 덮어쓰지 않는다. 결과는 `evaluation/extraction/comprehensive/results/policy-report.json`.

| 항목 | 이전 | 이후 |
|---|---|---|
| 미해결 원문 항목(원본 기록) | 117 | 117 (그대로 보존) |
| 작성을 막는 항목 | 117 | **55** (내용 누락 49, 응답 실패 6) |
| 경고 | - | 62 (구분선·제목·연결 문장 48, 약어 7, 재판독 중복 7) + 검증 제외 후보 124 |
| 작성용 사실 | 1,001 | 999 |
| 소수 쉼표로 표시된 사실 | - | 3 (`P0077R0F0002`, `P0077R0F0005` 작성용 → 제외, `P0077R0F0007`은 원래 제외) |
| 참조 42개 숫자 보존 대리 지표 | 보존 29, 숫자 누락 2(R09, R23), 수동 확인 11 | 동일 |

- 경고로 내려간 62개는 원문 텍스트와 대조해 하나씩 확인했다. `1560s도`(단위 뒤 한글 조사)와 `Output Dimension: 16`(라벨: 값)이 처음 규칙에서 잘못 내려가서, 수치 판정을 고쳐 막음으로 되돌렸다.
- 남은 55개는 사람이 원문을 보고 "진행 허용"하거나, 다음 추출 개선으로 줄여야 한다. 따라서 이 저장본은 아직 `ready_for_drafting=false`다.
- 참조 대리 지표는 21쪽 표본 42개의 **숫자 문자열 보존 여부만** 본다. 의미 판정이 아니다. 숫자가 없는 11개는 수동 확인 대상이다.

## 검증

- `python -B -X utf8 -m unittest discover -s tests`: 308개 통과. 기존 297개 + 새 11개.
- 새 테스트가 확인하는 것:
  - 소수 쉼표 판별과 오탐 방지
  - 사람 검토 사실 제외, 재적용 시 변화 없음
  - 막음/경고 분류
  - 원문 없을 때 보수적 처리
  - 저장본 불러오기 경로
  - 사람 허용 기록과 문구 결속
  - 질문 기반 모듈 격리
- Streamlit AppTest로 11/2 저장본을 근거 화면에 렌더링했다. 오류 0. "작성을 막는 항목 55개", "경고 항목 186개", 허용 폼(선택지 55개)이 표시됨을 확인했다.
- 외부 API 호출은 없다.
