# 3번: 장·절별 근거·지침의 입력 문맥 구성

연구 내용은 CUDA 연구 근거이고, 골든 논문은 구조·작성 방식의 참고 자료다. 이 단계는 **계획에 명시된 배정을 코드로 검증하고 장·소절 입력으로 만드는 작업**이다. 새 의미 평가 기준이나 장별 검토·수정 루프를 구현하는 단계가 아니다.

## 배정의 근거

기존 계획 호출에서 각 `required_item`에 `subsection_index`를 명시하게 했다. 0부터 시작하며, 소절이 없는 장은 0이다. 이 필드는 코드가 제목 키워드로 추측하지 않고 **계획 담당이 해당 필수 내용을 어느 소절에서 다룰지 정한 결과**다. 코드가 그 판단의 의미적 적합성을 입증하지는 않는다.

각 필수 항목에는 기존 `evidence_ids`, `guideline_ids`를 그대로 사용한다. 추가 배정 전용 모델 호출은 없다.

`evidence_ids`는 해당 필수 내용을 작성할 때 사용할 수 있는 후보 목록이며 전부 인용해야 하는 목록이 아니다. 작성·검토는 실제로 쓴 주장과 근거 연결을 확인하고, 미사용 후보는 오류로 취급하지 않는다. 반드시 필요한 비교 대상·조건·결과는 `description`에 명시하고 내용 충족 여부로 검토한다.

계획 담당은 작성할 주장과 내용을 먼저 구체화하고, 그 내용을 뒷받침하는 데 필요한 근거만 선택한다. 같은 주제의 로그나 반복 관측을 전부 필수 근거로 배정하지 않는다. 대표 근거를 고를 때 서로 다른 조건·비교 기준·반대 결과·실패·한계를 누락하지 않도록 지시하며, 근거 수에 고정 상한은 두지 않는다. 미선택 근거는 연구 자료에 남고, 미선택 자체를 미해결 과제로 취급하지 않는다. 이 선택의 의미적 적합성을 코드가 보장하지는 않는다.

```json
{
  "id": "comparison",
  "description": "동일 입력에서 두 조건의 관측 결과와 비교 한계를 설명한다.",
  "subsection_index": 0,
  "evidence_ids": ["baseline_fact", "changed_fact"],
  "guideline_ids": ["selected_guide_required_1"]
}
```

위 ID들은 형식 설명용이며 실제 연구 결과가 아니다.

## 코드가 구성하는 입력

| 입력 | 포함하는 내용 | 구성 방식 |
|---|---|---|
| 장 입력 | 장 계획, 배정된 근거 전체, 선택한 골든 지침, 배정된 표, 소절별 배정 목록 | 연구 전체에서 장의 `evidence_ids`, `reference_ids`, `table_ids`로 선택 |
| 소절 입력 | 해당 필수 항목에 명시적으로 배정된 근거, 관련 표 전체, 연결된 작성 기준, 공통 문체·흐름·전용 내용 이전 금지 지침 | `subsection_index`와 ID 연결로 선택 |
| 선행 장 문맥 | 제목·목적·역할·소절 목록 | 선행 장의 전체 본문이나 상세 근거를 덧붙이지 않음 |

### 문맥을 보존하는 규칙

- 근거의 statement뿐 아니라 **조건·한계·측정값·단위·귀속·원문 인용**도 그대로 유지한다. 글자 수로 자르거나 새 요약으로 대체하지 않는다.
- 비교 필수 항목에는 양쪽 근거를 배정해야 한다. 코드가 임의로 비교 상대를 찾아 만들어 주지는 않는다.
- 표에 연결된 근거 하나가 소절에 포함되면, 그 표의 다른 비교 근거도 함께 포함한다. 연결된 표가 여럿이면 이 관계가 더 이상 확장되지 않을 때까지 보존한다.
- 장에 배정됐지만 어느 필수 항목에도 배정되지 않은 근거는 각 소절에 자동으로 넣지 않는다. 여러 소절에서 필요하면 계획 담당이 각 소절의 필수 항목에 같은 ID를 명시적으로 연결한다. 관련 표의 비교 근거 확장을 제외하고, 나머지 근거는 장 입력과 원래 연구 자료에 보관한다.
- 선택된 골든 지침의 세부 `required_content/criteria`는 소절의 `guideline_ids`로 좁힌다. 목적·문단 전개·문체·`not_to_transfer`는 유지한다.
- 소절에 골든 기준을 연결하지 않은 연구 자체의 요구사항이 있으면, 그 소절에는 선택한 가이드 전체를 유지한다. 코드가 지침의 적용 대상을 추측해 삭제하지 않는다.

## 기존 계획과 잘못된 배정 처리

| 상태 | 처리 |
|---|---|
| 모든 필수 항목이 유효한 소절에 배정됨 | `explicit` 입력 구성 |
| 기존 계획처럼 소절 배정 정보가 전혀 없음 | `section_fallback`으로 기록하고 장 전체 근거를 각 소절에 유지 |
| 일부 항목만 배정됨 | 오류. 나머지를 임의로 분배하지 않음 |
| 없는 소절·소절 누락·잘못된 인덱스 | 오류. 계획 보정 대상 |
| 없는 근거·가이드 또는 표의 비교 근거 누락 | 오류. 해당 입력을 만들지 않음 |

이 호환 경로 때문에 소절 배정 정보가 전혀 없는 기존 계획에서는 문맥이 줄지 않을 수 있다. 서비스의 새 계획 스키마는 각 항목의 `subsection_index`를 필수로 요구한다. 명시 배정이 있어도 한 항목에 많은 근거가 선택되거나 표의 비교 연결이 넓으면 입력이 클 수 있다.

## 현재 서비스와의 연결 범위

- `paper_context.py`의 `build_contexts`가 장·소절별 입력을 생성한다.
- `PlannedPaper.run`은 계획 검증 뒤 문맥 파일을 저장한다. **작성 계획만 만들기**에서도 확인할 수 있다.
- 소절마다 배정된 입력으로 작성·검토를 독립 호출한다. 소절이 없는 장은 본문 하나를 작성·검토한다.
- 검토를 통과한 소절로 장별 1차 편집·검토를 진행한 뒤 전체 2차 편집·검토를 진행한다.
- 작성자와 두 편집자 모두 소절별 근거 배정을 코드로 검사한다. 단계별 재개·실패 처리는 [계층형 작성 흐름](HIERARCHICAL_DRAFTING.md)을 참고한다.
- 계획 담당은 전체 근거의 주장·조건·수치·한계를 받는다. `prepare_planning_research`는 추출 판정 설명(`support_note`, `supplemental_reason`), 중복 골든 지침, 이전 판정 및 원문 검증 이력을 계획 입력에서 제외한다. 질문 정의·현재 적용 여부·부족 필드·근거 연결과 질문별 최신 사용자 결정을 유지하며, 연구 JSON과 추출 이력은 그대로 보존한다. 40개 초과 근거의 원문 인용은 기존 방식처럼 계획에 전달하지 않되, 출처 ID·페이지·사용자 기록 귀속은 유지한다. 작성·원문 검토에는 전체 근거를 사용한다.
- 새 `context_version`을 실행 입력 해시에 포함해 이전 입력 구성과 새 구성의 실행 폴더를 구분한다.
- `paper-context-v2`와 변경된 계획 지침은 다음 실행에서 새 계획을 생성하게 한다. 이전 실행 폴더의 계획·완료 단계·초안은 보존된다. 이 변경은 근거 추출 단계를 다시 실행하지 않는다.
- 이후 문맥·작성자 지침 변경으로 실행 폴더가 달라져도 모델·계획 지침·계획 입력·스키마가 모두 동일한 완료 계획 응답은 재사용한다. 계획 지침이나 사용자 결정이 달라지면 새 요청이다. 재사용 기록은 응답 옆 `.reuse.json`에 저장한다. 이전의 넓은 근거 배정 계획을 새 계획 지침의 결과로 대신 쓰지 않는다.

## 계획 요청 실패와 진단

계획 생성 및 계획 보정에서 연결 실패·시간 초과가 발생하면 동일 요청을 1초 후 한 번만 재시도한다. HTTP 400 등 서버가 반환한 오류는 전송 오류로 재시도하지 않는다. 다른 단계의 전송 재시도 기본값은 그대로 0회다. 응답 대기 한도는 회당 300초로 유지되므로 두 번 모두 시간 초과라면 약 10분이 걸릴 수 있다. 입력 축소가 특정 응답 시간이나 실제 생성 성공을 보장하지는 않는다.

원래 응답 파일 옆 `.request.json`에는 입력·시스템 지침·스키마의 바이트 수, 시도별 시작 시각·소요 시간·HTTP 상태·오류 종류와 응답의 usage(서버 캐시 사용량 포함)를 기록한다. API 키와 인증 헤더는 기록하지 않는다. 전송 실패 기록은 `*-transport-error-*.json`에 별도로 남겨 재시도 성공 후에도 보존한다. 오류 메시지는 실패한 요청 이름과 ReadTimeout 등 실제 오류 종류를 표시한다.

## 저장되는 파일

작성 실행 폴더 안에 다음 파일을 저장한다. 모두 기존 `draft_history/` 아래이므로 Git에는 기본적으로 포함되지 않는다.

```text
plan.json
planning-input.json
context-allocation.json
contexts/
  sections/
    <section-id>.json
  subsections/
    <section-id>-p0.json
    <section-id>-p1.json
```

`context-allocation.json`에는 장·소절별 근거 ID, 지침 ID, `explicit/section_fallback` 여부와 직렬화한 입력 문자 수를 기록한다. `section_only_evidence_ids`는 최종 소절 입력에는 배정되지 않고 장에 남은 근거이며, 소절의 `table_expanded_evidence_ids`는 표의 비교 관계를 보존하기 위해 추가된 근거다. 명시 배정의 `shared_evidence_ids`는 빈 배열로, 장의 남은 근거를 공통 근거로 추론하지 않는다. 문자 수는 모델 토큰 수·실제 처리 시간·비용 측정이 아니다.

`planning-input.json`은 실제 계획용 연구 입력과 근거 수·입력 바이트 수를 기록한다. 연구 원본은 `research.json`에 따로 보관한다.

## 검증 범위

외부 API 없이 모의 계획·응답으로 확인했다.

- 무관한 장 근거가 소절 입력에 들어가지 않는지
- 비교 양쪽·표의 모든 근거·조건·한계·출처를 보존하는지
- 소절별 기준을 좁혀도 문체와 이전 금지 지침은 남는지
- 불명확하거나 잘못된 배정을 추측하지 않고 차단하는지
- 기존 계획은 전체 문맥을 유지하는 호환 경로로 처리하는지
- 계획 미리보기의 기존 모델 호출 1회만으로 입력 파일까지 저장되는지

실제 CUDA 논문을 새로 생성하거나 미해결 근거의 작성 게이트를 해제하지 않았다. 실제 계획의 배정 품질과 생성 품질 평가는 별도다.
