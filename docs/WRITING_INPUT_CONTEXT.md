# 3번: 장·절별 근거·지침의 입력 문맥 구성

연구 내용은 CUDA 연구 근거이고, 골든 논문은 구조·작성 방식의 참고 자료다. 이 단계는 **계획에 명시된 배정을 코드로 검증하고 장·소절 입력으로 만드는 작업**이다. 새 의미 평가 기준이나 장별 검토·수정 루프를 구현하는 단계가 아니다.

## 배정의 근거

기존 계획 호출에서 각 `required_item`에 `subsection_index`를 명시하게 했다. 0부터 시작하며, 소절이 없는 장은 0이다. 이 필드는 코드가 제목 키워드로 추측하지 않고 **계획 담당이 해당 필수 내용을 어느 소절에서 다룰지 정한 결과**다. 코드가 그 판단의 의미적 적합성을 입증하지는 않는다.

각 필수 항목에는 기존 `evidence_ids`, `guideline_ids`를 그대로 사용한다. 추가 배정 전용 모델 호출은 없다.

```json
{
  "id": "comparison",
  "description": "동일 입력에서 두 조건의 관측 결과와 비교 한계를 설명한다.",
  "subsection_index": 0,
  "evidence_ids": ["baseline_fact", "changed_fact"],
  "guideline_ids": ["selected_guide_required_1"]
}
```

위 ID들은 형식 설명용이며 실제 연구 결과가 아니다.

## 코드가 구성하는 입력

| 입력 | 포함하는 내용 | 구성 방식 |
|---|---|---|
| 장 입력 | 장 계획, 배정된 근거 전체, 선택한 골든 지침, 배정된 표, 소절별 배정 목록 | 연구 전체에서 장의 `evidence_ids`, `reference_ids`, `table_ids`로 선택 |
| 소절 입력 | 해당 필수 항목과 근거, 장 공통 근거, 관련 표 전체, 연결된 작성 기준, 공통 문체·흐름·전용 내용 이전 금지 지침 | `subsection_index`와 ID 연결로 선택 |
| 선행 장 문맥 | 제목·목적·역할·소절 목록 | 선행 장의 전체 본문이나 상세 근거를 덧붙이지 않음 |

### 문맥을 보존하는 규칙

- 근거의 statement뿐 아니라 **조건·한계·측정값·단위·귀속·원문 인용**도 그대로 유지한다. 글자 수로 자르거나 새 요약으로 대체하지 않는다.
- 비교 필수 항목에는 양쪽 근거를 배정해야 한다. 코드가 임의로 비교 상대를 찾아 만들어 주지는 않는다.
- 표에 연결된 근거 하나가 소절에 포함되면, 그 표의 다른 비교 근거도 함께 포함한다. 연결된 표가 여럿이면 이 관계가 더 이상 확장되지 않을 때까지 보존한다.
- 장에 배정됐지만 어느 필수 항목에도 배정되지 않은 근거는 **장 공통 근거**로 각 소절에 유지한다. 배정이 불명확하다는 이유로 버리지 않는다.
- 선택된 골든 지침의 세부 `required_content/criteria`는 소절의 `guideline_ids`로 좁힌다. 목적·문단 전개·문체·`not_to_transfer`는 유지한다.
- 소절에 골든 기준을 연결하지 않은 연구 자체의 요구사항이 있으면, 그 소절에는 선택한 가이드 전체를 유지한다. 코드가 지침의 적용 대상을 추측해 삭제하지 않는다.

## 기존 계획과 잘못된 배정 처리

| 상태 | 처리 |
|---|---|
| 모든 필수 항목이 유효한 소절에 배정됨 | `explicit` 입력 구성 |
| 기존 계획처럼 소절 배정 정보가 전혀 없음 | `section_fallback`으로 기록하고 장 전체 근거를 각 소절에 유지 |
| 일부 항목만 배정됨 | 오류. 나머지를 임의로 분배하지 않음 |
| 없는 소절·소절 누락·잘못된 인덱스 | 오류. 계획 보정 대상 |
| 없는 근거·가이드 또는 표의 비교 근거 누락 | 오류. 해당 입력을 만들지 않음 |

이 호환 경로 때문에 기존 계획에서는 문맥이 줄지 않을 수 있다. 실제 배정 결과를 보고 판단해야 하며, 장 공통 근거가 많을 때도 자동으로 작은 입력이 된다고 보장하지 않는다.

## 현재 서비스와의 연결 범위

- `paper_context.py`의 `build_contexts`가 장·소절별 입력을 생성한다.
- `PlannedPaper.run`은 계획 검증 뒤 문맥 파일을 저장한다. **작성 계획만 만들기**에서도 확인할 수 있다.
- 현재 장별 작성 호출은 새 장 입력과 소절별 ID 배정 목록을 사용한다. 장의 모든 소절을 한 호출에서 작성하는 기존 방식은 유지한다.
- 기존의 단일 소절 형식 보정 호출에는 해당 소절의 근거·조건·지침만 전달하며, 다른 소절의 근거를 사용할 수 없게 검증한다.
- 전체 검토·전체 편집 호출을 장별로 바꾸지 않았다. 4~6번의 검토·부분 수정·전체 연결 검토는 후속 단계다.
- 계획 담당에게 전체 근거를 전달하는 기존 경로도 이번에 바꾸지 않았다. 따라서 이번 변경만으로 전체 비용·속도 개선 수치를 주장하지 않는다.
- 새 `context_version`을 실행 입력 해시에 포함해 이전 입력 구성과 새 구성의 실행 폴더를 구분한다.

## 저장되는 파일

작성 실행 폴더 안에 다음 파일을 저장한다. 모두 기존 `draft_history/` 아래이므로 Git에는 기본적으로 포함되지 않는다.

```text
plan.json
context-allocation.json
contexts/
  sections/
    <section-id>.json
  subsections/
    <section-id>-p0.json
    <section-id>-p1.json
```

`context-allocation.json`에는 장·소절별 근거 ID, 지침 ID, 공통 근거, `explicit/section_fallback` 여부와 직렬화한 입력 문자 수를 기록한다. 문자 수는 모델 토큰 수·실제 처리 시간·비용 측정이 아니다.

## 검증 범위

외부 API 없이 모의 계획·응답으로 확인했다.

- 무관한 장 근거가 소절 입력에 들어가지 않는지
- 비교 양쪽·표의 모든 근거·조건·한계·출처를 보존하는지
- 소절별 기준을 좁혀도 문체와 이전 금지 지침은 남는지
- 불명확하거나 잘못된 배정을 추측하지 않고 차단하는지
- 기존 계획은 전체 문맥을 유지하는 호환 경로로 처리하는지
- 계획 미리보기의 기존 모델 호출 1회만으로 입력 파일까지 저장되는지

실제 CUDA 논문을 새로 생성하거나 미해결 근거의 작성 게이트를 해제하지 않았다. 실제 계획의 배정 품질과 생성 품질 평가는 별도다.
