# 2번 워크플로(연구 일지 → 작성 근거) 문제 정의와 개선 접근 · 검토 요청

작성: 2026-11-03. **코드 변경 없는 제안 문서다.** 접근 방법에 대한 확인을 받은 뒤 구현한다.

## 0. 요약

- 2번의 원래 목적은 **3번 초안이 쓸 근거를 정확하게 뽑는 것**이다. 기존 전체 수집(v3)은 v3부터 목적이 **원문 953개 요소의 장부를 빈칸 없이 채우는 것**으로 바뀌었다. 미해결이 1개만 있어도 3번을 막는 게이트가 붙으면서, 검사를 엄격하게 할수록 미해결이 늘어 수렴하지 않았다(40 → 117).
- 미해결 117개 중 상당수는 연구 내용이 아니거나 이미 보존된 내용이다(구분선·제목, 같은 문장의 재판독본, 약어 글자 검사). 실제 누락으로 보이는 건 약 31개다(키워드 기준 대략 분류).
- 11/2~11/3에 추가된 **요구사항 경로**(골든 지침 → 공통 질문 → 적용 판단 → 질문별 근거)는 방향이 맞다. 다만 전체 수집 경로에서 넘어온 구조적 문제 몇 가지가 남아 있다.
  - 전부-아니면-전무 게이트
  - 페이지마다 누적 근거 전체를 다시 보내는 요청
  - 순차 실행
  - 측정 기준 부재
- 제안: 요구사항 경로를 유지하고 다음을 순서대로 보완한다.
  - **(0) 골든셋으로 측정 기준을 먼저 세운다.**
  - **(1) 게이트 정책을 정리한다.**
  - **(2) 페이지 요청을 가볍게 하고 병렬화한다.**
  - **(3) 숫자 정규화를 코드로 검사한다.**
  - **(4) 질문별 근거 묶음(실험 카드)을 만든다.** 3번 입력과 연결되므로 3번 담당자와 합의가 필요하다.
  - **(5) 예산과 진행 표시를 넣는다.**

## 3. 요구사항 경로(11/2~11/3) 평가

### 3-1. 맞는 방향

- **질문 기반 선택**: 골든 지침에서 만든 공통 질문 52개로 필요한 근거만 찾는다. "원문 요소별 무조건 수집·누락 복구 루프"를 실행하지 않는다.
- **사람 개입(HITL)**: 모순 판정은 오류로 종료하지 않고 사용자 판단 대기로 전환한다. `accept_limited`로 범위를 줄여 진행할 수 있다.
- **질문 ID 연결**: 근거가 어느 질문(절)에 답하는지 연결되어 3번 배정에 쓸 수 있다.

## 5. 제안 단계

각 단계는 독립된 PR로 진행하고, 단계마다 0단계 측정 기준으로 전후를 비교한다.

### 0단계: 측정 기준 (API 없음)

- 기존 자료를 재사용해 **작성에 필요한 핵심 근거 골든셋**을 만든다.
  - 21쪽 표본의 핵심 사실 42개: `evaluation/extraction/benchmark/reference.json`
  - 수작업 E01~E12: `archive/manual-evidence/`
- 각 항목에 공통 질문 ID를 붙이고, 유형 태그를 단다.
  - happy: 핵심 실험 결과
  - edge: 조건·한계
  - failure: AI 조언을 작성자 성과로 오인하지 않음
  - critical: 소수 쉼표 같은 숫자 함정
- 지표(Pass/Fail):
  - 핵심 근거 재현율
  - 수치·단위·조건 정확도
  - 귀속(관측 / 계획 / AI 조언) 정확도
  - 3번으로 넘어가는 근거 수
  - 호출 수와 소요 시간
- 한계: 수작업 파일의 PDF 해시가 현재 원본과 다르다. 42개 참조는 21쪽 표본이다. 정식 점수가 아니라 회귀 비교용으로만 쓴다.
- 완료 기준: 기존 전체 수집 저장본과 요구사항 경로 결과를 같은 스크립트로 채점할 수 있다.

### 1단계: 게이트 정책 정리 (API 없음, 결정 필요)

- 작성을 **막는 것**과 **경고만 하는 것**을 나눈다. 제안은 아래와 같다.
  - 막음: 필수 질문의 `missing`/`uncertain` 중 사용자 처리가 없는 것, 작성 입력에 들어갈 근거의 숫자 오류
  - 경고만: 검증에서 제외된 후보(`excluded`)와 판독 불가 이미지. 이미 작성 입력에서 빠져 있으므로 검토 큐에 남기고 작성은 진행한다
- 실패·제외 사례는 어노테이션 큐(재검토 목록)로 모아 다음 개선의 입력으로 쓴다.
- 전체 수집 경로를 계속 쓸 경우에는 2-2의 가짜 미해결도 코드로 정리한다.
  - 구분선·라벨은 `no_research`로 분류한다
  - 재판독본은 원래 요소에 귀속한다
  - 약어 검사는 경고로 바꾼다
  - 저장본에 다시 적용해 남는 수를 측정한다
- 완료 기준: 게이트 판정 사유가 "막음 / 경고"로 나뉘어 화면과 JSON에 나온다.

### 2단계: 페이지 요청 경량화와 병렬화 (API 사용)

- `preserved_evidence`에 누적 전체를 넣지 않는다. 대안은 다음 중 하나다.
  - (a) 페이지는 독립적으로 추출하고, 같은 내용 병합은 코드의 정확 일치 병합과 사후 중복 검토로 처리한다.
  - (b) 인접 페이지와 같은 질문의 근거만 ID와 짧은 진술로 보낸다.
- (a)이면 페이지를 병렬로 처리할 수 있다. 원문 검토 묶음과 질문 충족 검사도 병렬화한다.
- 완료 기준: 0단계 지표가 같거나 좋으면서 요청 토큰과 소요 시간이 줄어든다.

### 3단계: 숫자 정규화 코드 검사 (API 없음)

- 검사 대상:
  - 소수 쉼표(`131,248s`)
  - 합계와 비율의 일관성(total 630.94s 대비 20.8%)
  - OCR 공백 숫자(`6 4ms`)
- `support_note`·검토 사유에 오류 지적이 있는데 `supported`이면 승인하지 않는다(판정 근거와 플래그 일치).
- 측정 범위가 같다는 확인 없이 값을 바꾸지 않는다. 수정 제안만 하고 사람이 승인한다.
- 완료 기준: `P0083F0001`, `P0084F0002` 유형이 회귀 테스트로 고정된다.

### 4단계: 질문별 근거 묶음, 실험 카드 (API 소량, 3번 담당자와 합의 필요)

- 같은 실험의 설정·조건·결과·해석을 카드 하나로 묶는다.
  - 표는 사실로 쪼개지 않고 구조화된 표 그대로 연결한다.
  - 카드는 질문 ID와 원자 사실 ID를 가진다.
- 3번 계획 단계는 카드(와 연구 요약)만 받는다. 장별 작성 때 배정된 카드의 원자 사실을 펼친다.
- 기존 `research.facts`는 그대로 두고 `research.evidence_cards`를 추가한다. 3번이 쓰지 않으면 동작이 바뀌지 않는다.
- 완료 기준: 3번이 카드를 입력으로 쓸지 합의되고, 계획 요청 크기가 줄어든다.

### 5단계: 예산과 진행 표시

- 단계별 시간·호출 수 한도를 둔다. 빈 JSON이 연속되면 재시도를 멈추고 해당 페이지를 큐로 보낸다.
- 단계별 진행 표시를 넣는다. 전체 수집 경로에서는 235/235 이후 원문 재검사 동안 진행 표시가 없어 정지로 오인했다.

## 6. 검토 요청 사항

1. **방향**: 전체 수집 경로를 더 고치지 않고 요구사항 경로를 기본으로 보완하는 데 동의하는가?
2. **게이트(1단계)**: 검증에서 제외된 후보와 판독 불가 이미지를 "막음"이 아니라 "경고"로 바꿔도 되는가? 현재 `excluded`가 작성을 막는 것이 의도된 정책인가?
3. **골든셋(0단계)**: 42개 참조와 E01~E12를 회귀 비교 기준으로 써도 되는가? 3번 관점에서 꼭 들어가야 할 근거가 더 있는가?
4. **3번 입력(4단계)**: `research.evidence_cards`를 추가하는 방식으로 3번과 연결해도 되는가?
5. **우선순위**: 수요일 멘토링 전까지 0~1단계(API 없음)를 먼저 하는 순서가 괜찮은가?

- 3번(계획·작성·검토) 흐름은 4단계 합의 전까지 건드리지 않는다.
