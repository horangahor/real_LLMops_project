# NPU 골든 논문 기반 초안 작성·평가 기준표 v1

작성일: 2026-10-31. 대상은 **현재 CUDA 연구일지로 작성할 논문 초안**이다.

이번 기준표의 골든 샘플은 **NPU 논문 한 편**이다. RGBD 논문의 기준은 혼합하지 않았다. 이 문서는 작성·평가 설계안이며 아직 실제 초안을 채점하거나 앱의 기본 골든 선택을 NPU 한 편으로 변경한 것은 아니다.

**2번 작업인 검사 책임 분리:** [기준별 코드·에이전트 책임표](WRITING_REVIEW_RESPONSIBILITIES.md)에 33개 항목의 판정 경계와 기존/미구현 검사를 정리했다. 입력 문맥 구성과 생성 흐름은 변경하지 않았다. 연구 주제는 CUDA이며 NPU 논문은 구조·서술 방식의 참고 자료다.

## 1. 출처와 기준의 성격

- 원문: [Benchmarking Vendor-Guided Optimizations on Edge NPUs: From NPU Only to End-to-End Performance](../golden%20sample/AIComps2026_NPU_Benchmarking_1.1v.pdf)
- PDF SHA256: `18d91e44744993d41db1fdd401fa0aadd2f7091d9fa1ebb84e4fbbc5bd5887e8`
- 기존 분석: [paper_structure_analysis.json](../paper_structure_analysis.json)의 위 원본 해시에 대응하는 NPU 프로파일. 현재 배열의 두 번째 프로파일이며, 실행 시 별칭은 `ref2`다. 배열 순서가 달라질 수 있으므로 NPU 선택의 기준은 원본 해시로 삼는다.
- 기계 판독용 기준: [npu-rubric.v1.json](../evaluation/writing/npu-rubric.v1.json)
- 원문 1~13쪽의 본문을 읽고, 실행 경로 그림·구성 표·결과 표·한계의 배치를 5·6·10·11·12쪽 렌더링으로 확인했다.

**C01~C08은 우리가 정하는 구현·검증 규칙**이다. 그 외 25개는 NPU 원문과 기존 `section_guidelines`에서 관찰한 작성 방식을 CUDA 연구에 맞게 풀어 쓴 기준이다. 아래의 통과 조건과 수정 정책은 NPU 저자가 제시한 공식 채점표가 아니며, 전문가 독립 검수나 성능 검증을 완료한 규칙도 아니다.

현재 NPU 프로파일에 남은 “세 가지 구성” 같은 표현은 문자 그대로 강제하지 않는다. 원문에 실제 존재하는 절과 본문을 우선하며, 오래된 `analysis_notes`의 설명만으로 절 존재 여부를 판단하지 않는다. 예를 들어 4.4 Limitations는 원문 12쪽과 현재 목차에 실제로 있다.

## 3. 공통 코드 검증 기준

코드는 실제로 확정할 수 있는 구조·식별자·선언된 계산 관계를 검사한다. 코드 통과가 과학적 내용의 정확성을 보증하지는 않는다.

| ID | 검사 기준 | 통과 조건 | 미달 시 처리 | 현재 구현 상태 |
|---|---|---|---|---|
| C01 | 장·절 구조 | 제목·순서·본문 칸이 계획과 일치하고 모델이 임의 제목을 추가하지 않음 | 해당 칸만 수정하고 제목은 코드로 재조립 | 기존 `compose_parts`, `validate_body` |
| C02 | 본문 근거 ID | 근거 표기가 있고, 사용한 ID가 그 장에 배정된 목록 안에 있음 | 없는 ID를 차단하고 해당 문단 수정 | 기존 `validate_body`. 모든 주장에 적절한 근거가 있는지는 에이전트 판단 |
| C03 | 계획의 연결 관계 | 장·필수 항목 ID가 고유하고 작성 순서·의존 관계·가이드 역할이 유효 | 작성 전에 계획 오류 반환 | 기존 `validate_plan` |
| C04 | 표 구조와 배치 | 표의 근거 ID와 행·열이 유효하고 코드가 배치하며 모델 본문이 새 표를 만들지 않음 | 잘못된 표를 차단. 값의 정확성은 별도 검사 | 기존 구조 검사와 `render_paper` |
| C05 | 골든 기준 연결 | 필수 항목의 `guideline_ids`가 그 장에서 선택한 가이드의 실제 기준 ID임 | 없는 기준·미선택 가이드 연결 차단 | 앞서 추가한 `validate_plan` 검사 |
| C06 | 검토의 본문 연결 | 실제 장의 문단 ID를 인용하고 모든 필수 항목이 정확히 한 번 검토됨 | 잘못된 검토 응답 거절, 이전 초안 보존 | 기존 `materialize_review`, `validate_review` |
| C07 | 수치·단위·계산 일관성 | 승인된 수치와 일치. 합계·비율은 동일 단위·측정 범위·분해 관계가 선언된 경우에만 계산 | 모순·소수 쉼표·측정 범위 불명확은 보류. 자동으로 그럴듯한 값으로 고치지 않음 | 초안용 범용 검사는 **추가 구현 필요** |
| C08 | 근거 성격과 귀속 | 계획·가설·해석·AI 조언 메타데이터를 유지하고 본문도 그 성격으로 표현 | 성과로 격상한 문단을 수정 또는 보류 | 메타데이터·프롬프트는 존재. 문장 의미 판정은 에이전트 필요 |

특히 C07은 현재 발견한 `131.248s`와 `131248s` 같은 수치 문제를 다룬다. 숫자만 원문에 등장한다고 통과시키지 않고 단위와 측정 범위를 함께 확인해야 한다.

각 행의 기존 JSON 연결은 기계 판독용 파일의 `profile_role`, `profile_required_indices`에 기록했다. 인덱스는 사람이 읽는 **1부터 시작하는 순번**이다. 예를 들어 D11은 NPU 프로파일 methods의 두 번째 `required_content`, 현재 별칭으로 `ref2_methods_required_2`에 대응한다. I01처럼 복수 지침을 결합한 항목도 있다.

## 5. 검토에 넘길 최소 문맥

| 검토 종류 | 입력으로 전달 | 기본적으로 제외 | 반환할 내용 |
|---|---|---|---|
| 코드 검사 | 계획, 근거·표 객체, 본문·문단 ID, 선언된 수치 관계 | 골든 PDF 전체·연구일지 전체·모델 호출 | 규칙 ID, 실패 위치, 오류 내용 |
| 장·절 의미 검토 | 해당 본문, 필수 항목, 적용 기준 행, 배정 근거의 조건·한계·인용 원문 | 무관한 실험 로그와 다른 장 전체 | 기준 ID, 판정, 실제 문단 ID, 관련 근거 ID, 짧은 이유 |
| 비교 검토 | 비교 문단, 양쪽 구성의 근거, 측정 구간과 통제 조건 | 비교와 무관한 원문 | 조건 일치·해석 가능 여부와 해당 근거 |
| 전체 연결 검토 | 목차, RQ 대응표, 장별 요약, 핵심 주장·용어 목록 | 원시 연구일지 전체와 모든 상세 근거 | 불일치한 위치와 필요한 문단 요청 |

입력을 줄일 때 비교의 한쪽 근거, 측정 조건, 한계, 앞뒤 캡션을 잘라내지 않는다. 요약은 구조를 잡는 용도이며 상세 근거를 삭제하거나 대체하는 자료가 아니다. 필요한 경우 관련 문단·인접 문맥을 추가로 가져온다.

## 6. 판정과 미달 처리

1. **코드:** `pass / fail / needs_check`.
2. **에이전트:** `met / partial / missing / needs_check / not_applicable`.
3. `met`은 기준 ID와 실제 문단 ID를 제시해야 한다. 연구 주장이면 해당 근거 ID도 필요하다. 실제 문단·근거의 존재는 코드가 확인하고 의미 충족은 에이전트가 판단한다.
4. `not_applicable`은 연구 범위에 따른 사유가 필요하다. 자료가 없는데 해당 성과를 주장한 경우에는 `needs_check`다. 수행하지 않은 실험을 쓰거나 단순히 항목을 제외해 통과시키지 않는다.
5. 중요 항목의 `partial / missing / needs_check`는 완료 승인으로 처리하지 않는다. 수정 가능한 문단만 수정하거나 후보 초안으로 보존한다. 문체 항목의 부분 미달은 지적을 남기고 무한 수정을 피한다.
6. **제안하는 운영 정책:** 한 장의 문제 부분만 최대 2회 수정·재검토한다. 이후에도 미달하면 후보와 지적을 보존한다. 근거 부족은 반복 생성으로 해결하지 않고 저자 확인으로 남긴다. 이 정책은 이번에 새로 설계한 것으로 현재 전체 편집 루프에 아직 연결하지 않았다.

```json
{
  "criterion_id": "D11",
  "section_id": "methods_framework",
  "verdict": "needs_check",

  "action": "측정 범위를 저자에게 확인. 전체 실행 시간이라고 임의 수정하지 않음"

```

## 7. 이번 기준표로 아직 하지 않은 일

- 기존 코드 테스트 개수와 이 기준표의 항목 수는 다르다. 이 기준표는 **33개 기준(공통 8개 + 장·절별 25개)**이며 실제 초안의 평가 통과 결과가 아니다.
- 기준표 JSON의 `status`는 `authored_not_runtime_integrated`다. C01~C06 등 기존 검사 기능은 있지만, 이번 기준표를 읽어 판정하는 실행기와 중요도별 승인 처리는 아직 연결하지 않았다.
- 앱은 현재 기존 두 논문의 프로파일을 읽는다. 다음 연결 작업에서 원본 해시로 **NPU 프로파일만 선택**해야 한다. 이 문서를 작성하면서 기존 JSON을 삭제하거나 실행 경로를 변경하지 않았다.
- NPU 골든 파일은 글의 구성·설명 기준이며 CUDA 연구 사실의 출처가 아니다. 현재 연구 근거에 남은 수치 오류·미해결 항목을 통과시키는 수단으로 사용하지 않는다.
- 실제 초안의 품질 평가는 별도다. 먼저 근거가 확인된 한 장에 적용해 판정과 수정의 적절성 및 처리 시간을 확인한 뒤 전체로 확대한다.
