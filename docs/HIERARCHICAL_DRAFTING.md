# Adaptive 계층형 작성과 검토

`PlannedPaper.run`은 작성 계획·근거 배정·표 배치를 검증한 뒤 `hierarchical_drafting.py`를 실행한다. 계획의 소절 수만큼 작성자를 호출하며, 소절이 없는 장은 본문 하나를 작성한다. placeholder 장은 제목만 출력한다.

## 실행 흐름

1. 소절 작성 → 승인 근거 사용·필수 내용 검토
2. 1차 편집: 소절들을 절로 구성 → 편집 품질 검토
3. 2차 편집: 절들을 논문으로 구성 → 전체 편집 품질 검토

첫 검토는 `bounded_review.py`, 두 편집 검토는 `editorial_review.py`에서 수행한다. 서로 다른 입력·프롬프트·응답 스키마를 사용한다.

## 소절 검토: approved-facts-v1

입력은 해당 소절의 본문 문단, 작성 계획, 승인된 후보 근거의 statement·조건·수치·한계·주장 성격·사용자 승인 범위다. 근거 원문의 sources.quote, source_elements, 추출 과정의 원문 검토 이력은 보내지 않는다.

- 실제 본문의 주장과 인용한 승인 근거가 맞는지 확인한다.
- 원문 출처·진위는 다시 심사하지 않고 원문 인용문을 생성하지 않는다.
- `required_item.evidence_ids`는 후보 목록이다. 미사용 후보를 실패 이유로 삼지 않는다.
- 필수 내용의 충족 여부는 description과 연결된 작성 기준으로 판단한다. 비교 양쪽의 조건·결과가 필요하면 description에 명시한다.
- 보고한 사용 근거 ID가 실제 문단에 인용됐는지, 허용된 항목의 후보인지 코드로 확인한다.
- 모델이 충족으로 판단하고 보고한 사용 근거가 다른 실제 문단에 인용돼 있으면, 코드가 그 문단 ID를 검토 기록에 연결한다. 본문·인용·판정은 바꾸지 않고 별도 모델을 호출하지 않는다.
- 실제 인용도 없거나 내용·근거 연결이 잘못됐으면 해당 작성자가 수정한다.

입력이 크면 본문 문단과 사용 근거를 예산 안에서 나누어 대조한다. 이 경우에도 원문을 재검증하지 않는다. 모든 실제 문단/인용 ID가 검사 범위에 포함됐는지 코드로 확인한다. 필수 내용 검토에는 근거 내용과 한계를 함께 전달한다.

## 절·전체 편집 검토: editorial-v1

입력은 목차·절 목적과 실제 본문 문단뿐이다. 연구 근거·원문·필수 근거 목록은 전달하지 않는다.

- 1차 편집 검토: 소절 간 중복, 문단 연결, 설명 순서, 용어·문체의 일관성.
- 2차 편집 검토: 절 간 중복, 전체 흐름, 서론·결론의 호응, 글의 통일성.
- 응답은 duplication / flow / organization / terminology / style 유형의 issues만 받는다. 내용·근거 심사를 위한 checks나 source_quote를 요청하지 않는다.
- 하위 소절에서 완료한 내용·지침 검토 결과는 기록으로 승계한다. `required_content_coverage`와 `reference_application`에는 `rechecked=false`와 승계 범위를 표시한다. 최종 본문을 다시 사실 검증했다는 의미가 아니다.
- 같은 필수 항목이 여러 소절의 호환 입력에 반복돼도 승계 충족률에서 중복 계산하지 않는다.

큰 본문은 인접 문단을 겹쳐 나누어 모든 문단·인접 연결이 편집 검토에 포함되도록 한다. 단일 문단이나 인접 문단 쌍 자체가 입력 예산을 넘으면 자르거나 검토를 생략하지 않고 중단한다.

## 수정과 기본 검증

실제 문제를 발견하면 해당 단계의 작성자 또는 편집자만 수정한다. 최초 작성과 내용 수정 최대 2회, 각 시도에서 형식 보정 최대 1회를 허용한다. 검토 응답의 JSON·ID 오류도 본문을 바꾸지 않고 응답 형식만 최대 1회 보정한다.

없는 근거 ID, 소절 범위 밖 인용, 없는 문단, 장·본문 칸 누락, 제목·표 직접 생성, 체크포인트 해시 불일치는 코드로 계속 차단한다. 편집 문제는 해당 문단·편집 단계로 되돌리고 소절 내용 검토를 다시 실행하지 않는다.

`verify_findings`, 원문 인용문 재생성·대조, 별도 인용 보정 에이전트는 현재 실행 경로에서 호출하지 않는다. `review_findings.py`, `citation_repair.py`의 함수는 과거 응답 진단·재생용으로만 남아 있다.

## 저장과 재개

각 단계는 `workflow/subsection-<id>-p<n>`, `workflow/section-<id>`, `workflow/paper`에 저장한다.

- responses/: 개별 모델 응답·호출 캐시
- candidate.json: 후보 본문과 현재 검토 결과
- reviews.json: 해당 단계의 검토·수정 이력
- approved.json: 입력 식별자·본문·검토를 묶은 승인 체크포인트
- checkpoint-history/: 이전 승인과 정책 전환 기록 보존
- review-*-diagnostics.json, failure-details.json/md: 실제 본문·근거 사용 또는 편집 지적의 진단 기록

새 검토 정책은 개별 요청에 반영해 이전 원문 대조·지적 재심사 실패 캐시를 재사용하지 않는다. 계획·작성 입력 식별자는 유지한다. 승인된 소절 본문은 기본 검증 뒤 재사용하며, 이전 통합 근거 검토로 승인된 절·전체 본문은 재작성하지 않고 새 편집 검토만 수행한다. 수정된 하위 본문으로 편집 입력이 달라지면 해당 상위 편집만 다시 수행한다.

모든 단계가 통과하기 전에는 draft.md와 마지막 정상 초안 포인터를 갱신하지 않는다. 중단·수정 후보와 원래 응답은 보존한다. 모델의 의미 판단은 여전히 저자 검토를 대체하지 않는다.
