# Adaptive 계층형 작성과 검토

`PlannedPaper.run`은 작성 계획·근거 배정·표 배치를 검증한 뒤 `hierarchical_drafting.py`를 실행한다. 계획의 소절 수만큼 작성자를 호출하며, 소절이 없는 장은 본문 하나를 작성한다. placeholder 장은 제목만 출력한다.

작성 계획 프롬프트는 골든 논문에서 추출한 `reference_shapes`의 장·소절 계층과 역할별 작성 가이드를 따르도록 지시한다. 각 작성 장의 `subsections`에 연구 내용에 맞는 소절을 계획하고 필수 항목·근거를 배정한다. 소절을 생략해 장 수준으로 평탄화하지 않으며 계획에는 본문 분량 목표·상한을 전달하지 않는다. 소절 제목·설명 범위는 이번 연구에 맞게 구체화하고 골든 논문의 실험·수치·연구 사실은 옮기지 않는다. 별도의 소절 최소 개수 검사나 계층 전용 보정 단계는 추가하지 않는다. 변경한 계획 프롬프트는 기존 실행 식별자에 반영되며, 기존 초안·완료 포인터·원문·근거 캐시는 보존한다. 이미 소절 없이 생성된 본문을 표시 단계에서 임의로 나누거나 예전 목차를 덮어씌우지 않는다.

`planning_wire.py`의 `derived-chapter-evidence-v2`는 기존 프로젝트 검증 범위(장 2개 이상·프로젝트 최대 장 수, 프로젝트 최대 소절 수)를 전송 스키마에도 반영한다. 새 개수 기준을 추가하지 않는다. `subsections`에는 소절 제목 문자열만 두고 목적·근거·필수 항목은 장의 별도 필드로 반환하도록 명시한다. `generation_order`에만 있고 장 객체가 없는 ID는 장 개수 오류에 실제 개수·허용 범위와 함께 표시한다. 보정은 기존 계획 보정 기회를 사용하며 JSON 조각을 제목으로 추측하거나 누락된 장을 코드로 생성하지 않는다. 정상 구형 계획 응답은 재사용하고 장 목록·작성 순서가 불완전한 구형 응답은 보존한 채 새 요청으로 전환한다. 새 형식의 계획은 기존 검증과 보정 캐시를 거치므로 성공한 보정 계획을 재개할 때 추가 호출하지 않는다.

최종 표 배치는 `publication_tables.py`의 `table-explanation-units-v3`를 사용한다. 계획한 소절에서 표 근거를 인용한 독립 문단 바로 앞에 표를 둔다. 후보 설명이 적은 표부터 연결하고 각 문단 앞에는 표 하나만 배치한다. 독립 설명이 없거나 다른 표와 설명을 공유할 수밖에 없으면 표를 보류하고 `withheld_tables`에 사유를 기록한다. 자리 확보를 위해 본문을 이동·복제·삭제하거나 새로운 설명을 만들지 않는다. `planned`는 계획한 표 수, `selected`는 실제 출력 수다. 본문 표 번호는 실제 배치 순서로 연속 부여한다.

공통 `academic-composition-v3` 지침은 계획·작성·기존 편집에 표 하나당 독립 해석 문단 1~2개를 배정한다. 소절 구성 점검은 표 근거와 인용으로 연결된 문단이 0개 또는 3개 이상이면 기존 보완 기회에서 설명 정리를 요청한다. 이는 의미 대응을 완전히 입증하는 검사가 아니며, 보완 후에도 남은 문제는 기존 경고 정책으로 보존한다. 기록자·작성자·연구노트의 저자를 외부 관찰자로 서술하는 표현도 기존 문체 보완에 연결한다. 문체를 이유로 주장·귀속·확실성 수준을 자동 치환하지 않는다.

`publication-table-view-v2`는 열 제목이 변수 할당·파이프 구분 실행 결과 조각으로 파싱된 원시 트레이스 표를 출판 후보에서 보류한다. 정상적인 파라미터 비교 열 이름만으로는 트레이스로 판정하지 않는다. 제목은 계획의 학술 제목, 원표의 제목, 유효한 열 이름 순으로 선택하며 내부 source_table ID를 표 제목으로 출력하지 않는다. 주석은 kind=unit/condition/abbreviation/uncertainty/missing_value/statistical_definition 또는 명시적인 단위·측정 조건·약어 등의 접두사를 가진 설명만 출력한다. 분류하지 못한 원문 부연은 `notes.withheld`에 보존한다. 자료별 문구를 매칭하는 예외는 없다.

화면은 `load_latest(refresh_layout=True)`로 저장된 최종 본문·표를 다시 조립해 기존 초안에도 새 배치를 적용한다. 이미 열린 adaptive 세션도 배치 정책이 바뀌면 저장 초안과 동일한 표시 본문만 갱신한다. 새 계획 미리보기와 다른 모드 본문은 덮어쓰지 않는다. 화면·텍스트·Markdown 다운로드는 같은 결과를 사용하며 API 호출과 파일 쓰기는 없다. 원래 `draft.md`·검토 기록·체크포인트는 유지하고, 기본 `load_latest()`는 종전 저장본을 그대로 반환한다. 새 완료 포인터에는 본문·연구 JSON의 체크섬도 저장해 다시 조립할 입력을 확인한다. 구형 스냅샷에 이 필드가 없으면 기존 초안·계획·검토 무결성 확인을 유지하며, 원본 JSON이 없는 스냅샷은 저장된 초안을 그대로 표시한다.

## 실행 흐름

소절 내용 보완의 기존 문단은 `paragraph-replacement-v1`로 1:1 대체한다. 문단별 요청은 정확한 원문·인용/비교 근거·해당 문단에 연결된 지적만 수정 의무로 받는다. 근거가 겹친다는 이유로 절의 다른 필수 항목을 붙이지 않는다. 미충족 검토 항목도 명시적으로 해당 문단에 배정된 경우만 포함하며, 계획의 다른 항목은 `section_context`의 읽기 전용 설명이다. 소절 전체 분량 지적은 모든 문단의 반복 재작성 과제나 절·전체 편집의 축약 과제로 전달하지 않고 작성 단계의 보완·경고 기록에 유지한다.

교체 출력의 `parts.p0`는 단일 `text/evidence_ids` 객체다. 문단 배열이나 여러 문단을 담은 text를 그대로 적용하지 않는다. 문단 하나를 여러 근거 요청으로 나누어 각 답변을 이어붙이지 않는다. source_body는 한 번만 대체되고, 원문의 문단 수·순서를 유지한다. 명시적인 누락 근거 보완은 기존 missing_evidence 작업에서 따로 기록한다.

문단의 글자 수는 원문과 현재 배정 예산·문단 상한으로 정한다. 여유 예산이 있으면 기존 허용 비율 범위에서 증가할 수 있고, 소절 예산이 이미 소진됐으면 원문보다 길어지지 않게 한다. JSON 스키마의 text.maxLength와 반환 후 실제 글자 수를 함께 검사한다. 여러 문단·과도한 분량이면 1회 보정하며, 계속 증식하면 해당 원문을 그대로 보존하고 paragraph_revision_deferred 경고를 남긴다. 입력 자체가 예산을 넘는 경우에도 원문·비교 근거를 자르거나 여러 교체 결과를 합치지 않고 미해결로 보존한다. 잘못된 인용 ID·빈 근거·깨진 본문 형식은 계속 차단한다.

새 교체 요청의 정책·스키마로 기존의 증식한 보완 캐시를 재사용하지 않는다. 원래 응답과 실패 후보 파일은 삭제하지 않으며 최초 작성 캐시·정상 승인 단계는 기존 정책대로 재사용한다. 이미 커진 후보를 문자열 처리로 축약하지는 않는다. 중단된 단계가 다시 실행되면 최초 작성 결과에서 새 보완 요청을 구성한다. `*-paragraph-replacement-v1-applied.json`과 split manifest에 원문 문단 ID·전후 글자 수·문단 수·원문 보존 여부를 기록한다. 새로운 상시 에이전트나 내용 검토 기준 완화는 추가하지 않는다.

계획의 `table_ids`가 표 선택의 기준이다. 모델이 선택에서 뺀 기존 표를 `table_placements`에 남긴 경우, `bind_plan_evidence`가 그 배치 항목만 제외하고 `table_placement_normalizations`에 원래 항목과 사유를 기록한다. 표를 새로 선택하거나 다른 절로 이동하지 않는다. 원래 캐시 응답은 보존한다. 알 수 없는 표 ID·선택된 표의 잘못된 소절 번호·빈 사유·누락·중복 배치는 계속 거부하고 장·표·위치를 오류에 표시한다.

공통 구성 규칙은 `writing_policy.json`에서 관리한다. 계획 요청에 핵심 질문·대표 근거·표 선별 규칙을 넣고, 작성·기존 편집에 각각의 규칙을 전달한다. 계획 규칙 변경은 새 요청 지문과 작성 실행 폴더를 만들며, 기존 근거 수집 캐시와 완성 초안은 보존한다. 자세한 적용 책임은 `docs/WRITING_COMPOSITION_POLICY.md`에 있다.

계획의 `evidence_ids`와 `required_items.guideline_ids`는 동일 ID 중복만 첫 등장 순서대로 제거한 뒤 검증한다. 작성 기준의 정리 이력은 `guideline_id_normalizations`에 장·필수 항목·제거한 중복 ID로 기록한다. 캐시의 원래 모델 응답은 변경하지 않는다. 실제로 없는 기준이나 선택하지 않은 골든 가이드의 기준은 제거·치환하지 않고 계속 거부한다. 직접 검증 시에는 중복과 잘못된 가이드 연결을 서로 다른 오류로 알린다.

신규 계획 요청은 `planning_wire.py`의 `derived-chapter-evidence-v2`를 사용한다. 모델은 필수 항목별 `evidence_ids`와 표 선택을 반환하고 장별 `evidence_ids`를 중복 출력하지 않는다. 코드는 선택한 필수 항목·표의 실제 근거 ID를 장에 합친 뒤 기존 검증과 소절 배정을 수행한다. 저장된 계획에는 종전과 같이 장별 목록도 포함한다. 기존 완료 응답에 명시된 장별 목록은 그대로 보존하며 같은 입력·지침의 정상 구형 스키마 완료 캐시도 우선 재사용한다. 실패한 전송은 완료 캐시로 취급하지 않는다.

계획·계획 보정 요청의 전송 JSON만 `compact-json-v1`으로 직렬화해 키·값 사이의 불필요한 공백을 줄인다. 문자열 내부 공백, 주장·수치·조건·한계·출처·사용자 승인 정보는 유지한다. 작성·편집·검토 전송 형식에는 적용하지 않는다. `planning-input.json`의 `serialized_input_bytes`와 실제 `.native.request.json`의 `input_bytes`에 전송 크기를 기록한다. 정책 변경은 별도 실행 식별자로 기존 초안을 보존한다. 새 단계·에이전트를 추가하거나 300초 대기 한도·전송 재시도 1회를 늘리지 않으며, 이 최적화가 실제 응답 지연 해소를 보장하지는 않는다.

1. 소절 작성 → 승인 근거 사용·필수 내용 검토
2. 1차 편집: 소절들을 절로 구성 → 편집 품질 검토
3. 2차 편집: 절들을 논문으로 구성 → 전체 편집 품질 검토

첫 검토는 `bounded_review.py`, 두 편집 검토는 `editorial_review.py`에서 수행한다. 서로 다른 입력·프롬프트·응답 스키마를 사용한다.

입력 예산 안에 든 소절의 통합 검토도 모델이 최초·JSON 재시도 모두에서 불완전한 JSON을 반환하면 `review-json-split-fallback-v1`로 기존 분할 검토 경로를 사용한다. 승인 근거 사용 검토와 필수 내용·가이드 반영 검토를 기존 구현대로 수행하며, 새 에이전트 계층이나 추가 본문 재작성은 없다. 같은 본문 전체를 보존하고 실제 인용의 검토 범위를 점검하며, 완료한 분할 응답은 재사용한다. 원래 실패한 두 응답은 수정하지 않고 `*-split-review-fallback.json`에 본문 체크섬·전환 사유를 남긴다. 통신 오류·HTTP 오류·ID 검증 오류는 이 전환 조건이 아니며, 분할 검토에서도 JSON을 받지 못하면 근거 연결이나 빈 issues를 추측해 승인하지 않는다. JSON 오류에는 요청 파일명·파싱 위치를 표시하고 요청 감사 파일에 종료 사유·응답 글자 수·파싱 오류를 기록한다.

소절 작성의 신규 요청은 문단별 `text`와 `evidence_ids` 형식을 사용한다. 기존 작성 프롬프트의 본문 `[근거:ID]` 직접 출력 지시는 실제 전송할 때 구조화된 근거 필드 지시로 치환해 상충하는 지시를 함께 보내지 않는다. 실행·계획 식별자는 유지하고 기존 완료 응답을 먼저 검사하므로 정상 작성 캐시는 재사용한다. 본문 인용과 별도 근거 목록이 어긋나면 양쪽 ID와 미허용 본문 ID를 보정 요청에 명시한다. ID 접두사를 추측해 바꾸거나 서로 다른 인용을 자동으로 합치지 않는다. 기존의 일치하는 중복 표기 정규화와 엄격한 배정 범위 검사는 유지한다.

한 문단 교체도 `paragraph-citations-v2`로 같은 인용 규칙을 명시한다. 전송할 때만 `source_body`의 표시용 인용을 `source_evidence_ids`로 분리하며, 원래 본문·근거·조건·원문 캐시는 보존한다. 모델은 인용 표시 없는 `text`와 실제 사용한 `evidence_ids`를 반환한다. 문단 배열용 규칙을 제거하면서 인용 규칙까지 빠졌던 이전 교체 요청은 본문 인용과 별도 근거 목록을 함께 반환할 수 있었다. 이전 정상 교체 응답은 현재 검증을 통과하면 재사용하고, 불일치 응답은 보존한 채 새 입력으로 요청한다. 새 응답·보정 진단에는 별도 인용 정책 이름을 붙여 이전 실패 기록을 덮어쓰지 않는다. 보정은 기존 1회이며, 잘못된 ID를 추측해서 맞추거나 형식 오류를 자동 승인하지 않는다.

검토자가 `met`으로 답했지만 문단·근거 목록을 비우거나 선택을 빠뜨린 경우, 본문 누락과 구분해 `검토 연결 미완료`로 표시한다. 빈 목록을 장 전체의 인용 누락 목록으로 확장하지 않는다. 이미 보고한 근거의 실제 인용 문단이 있으면 기존 코드 연결을 사용하고, 여전히 불완전한 항목만 `review-link-completion-v1`로 기존 검토자에게 1회 보정 요청한다. 본문·해당 항목의 설명·사용자 승인 범위만 전달하며 근거 원문·다른 항목을 다시 검토하거나 본문을 쓰지 않는다. 기존 ID·JSON 형식 보정 기회는 유지한다.

보정 후에도 선택이 불완전하거나 검토자가 `needs_check`로 답하면 `review_link_incomplete` 경고로 보존하고 편집으로 진행한다. 입력 예산을 넘으면 본문을 자르지 않고 같은 미완료 경고를 남긴다. 필수 항목 충족률과 원래 판정을 충족으로 올리지 않으며 `review_status=incomplete`, `content_approved=false`를 유지한다. 존재하지 않는 ID·다른 장의 문단·범위 밖 근거·깨진 응답과 실제 본문 내용 오류는 이 경고 전환에 포함되지 않는다. 항목별 보정 결과와 본문 체크섬은 `*-review-link-completion-v1.json`, 전체 경고는 기존 `review-warnings.json`에 남긴다. 승인 체크포인트는 보완 기록을 함께 저장해 재개 시 본문·검토 호출 없이 동일한 경고를 복원한다.

참고 가이드의 `applied`·`partial` 판정에 문단 선택이 없으면 기존 검토 응답 보정 1회를 수행한다. 보정 후에도 빈 목록이면 `reference-link-completion-v1`로 처리한다. 원래 판정·사유는 `model_verdict`와 원본 응답에 보존하고, 검증할 본문 연결이 없으므로 유효 판정은 `not_visible`, 확인 상태는 `incomplete`로 내린다. 이는 가이드가 실제로 미반영됐다는 확정 판정이 아니다. `reference_link_incomplete` 경고를 기존 경고 모음에 남기며 본문 재작성이나 추가 에이전트 호출은 하지 않는다. 전체 응답을 다시 검증해 알 수 없는 ID·다른 장 문단·누락된 검토 행·다른 지적의 오류를 숨기지 않는다. 보고서는 미완료 가이드를 반영 완료·부분 반영·실제 미반영 수에 합치지 않고 `reference_application.incomplete`로 집계한다. 정상 연결된 가이드와 내용 지적은 유지하고, 승인 체크포인트와 상위 편집에도 미완료 상태를 계승한다. 원본 응답·후보 본문은 보존하며 `*-reference-link-completion-v1.json`에 변환과 체크섬을 기록한다.

본문 인용 없이 여러 문단을 하나의 `text`에 넣고 근거를 합쳐 반환한 경우는 `JoinedParagraphsError`로 구분한다. 본문 인용 누락으로 진단하거나 전체 근거를 모든 문단에 자동으로 붙이지 않는다. `prose_format_repair.py`가 기존 형식 보정 1회를 사용해 고정 문단별 근거 목록만 반환받는다. 본문과 문단 순서는 코드가 보존하며 모델은 본문을 출력하지 않는다. 후보는 원래 객체가 선택한 배정 ID로 제한하고 승인 근거의 내용·조건·한계·사용자 지침을 함께 전달한다. 원문 출처를 다시 검증하는 단계는 추가하지 않는다. 빈 목록·새 ID·누락된 문단은 적용하지 않고 진단을 보존한다. 정상 연결도 후속 소절 내용 검토를 거친다. 원래 응답·문단별 연결·정규화 결과와 본문 재작성 여부는 별도 JSON에 보존하며 완료한 보정 응답은 캐시로 재사용한다.

## 본문 분량 목표: subsection-length-v2

분할 수정의 신규 전송 입력은 `fragment-review-scope-v2`로 현재 문단과 공통 지적만 전달한다. 같은 근거가 연결됐거나 경고의 evidence_ids가 비어 있다는 이유로 다른 문단의 검토 인용문을 함께 보내지 않는다. 원래 검토·인용문은 단계 기록에 보존한다. 형식 보정에도 실패 본문 전체를 반복 전송하지 않고 오류 사유를 전달한다. facts·원문·표·source_body·사용자 지침은 그대로 유지한다. 예전 분할 응답은 현재 묶음의 본문·ID 검증을 통과하는 경우 재사용하며, 잘못된 응답 캐시는 보존한 채 수정된 입력으로 요청한다. 문단 합침 형식 보정은 기존 본문 보존 경로를 유지한다. `*-revision-input-scope.json`에는 이전/현재 지적의 문단 ID와 원문·본문·표 유지 여부를 기록한다. 묶음 구성과 완료한 단계는 초기화하지 않는다.

화면의 **논문 본문 목표 글자 수**는 기본 30,000자다. `PAPER_DRAFT_TARGET_CHARS`로 기본값을 바꾸거나 CLI의 `--writing-target-chars 20000`으로 지정할 수 있다. 인용 표시·제목·표를 제외하고 공백을 포함한 글자 수다. 0은 이전의 목표 없는 작성 정책을 그대로 사용한다. 근거 수집의 두 모드는 지원하며, 과거 CUDA 고정 구성 작성 경로는 제거했다.

`writing_length.py`는 확정된 계획의 절에 역할별 가중치(방법·결과·평가 4, 논의 3, 나머지 2)를 적용하고, 각 절의 몫을 실제 소절 수로 나눈다. placeholder는 제외한다. `academic-composition-v5`의 기본 상한은 소절 2,000자·절 6,000자·문단 600자다. 분량 허용 비율 125%를 고려해 소절 목표는 최대 1,600자, 절 배정 목표는 최대 4,800자로 잡는다. 수치 목표·상한은 소절 작성·보완 요청에만 전달하며, 계획이나 편집 요청에는 넣지 않는다. 상한을 적용하면 소절 목표의 합은 전체 설정보다 작을 수 있고, 남는 예산을 억지로 다른 소절에 채우지 않는다. `allocated_target_chars`가 실제 배정 목표의 합이다. 후보 근거가 많다는 이유로 본문 목표가 커지지 않는다.

최종 결과의 소절·절 합계와 문단 길이는 확인용으로 집계하고 초과하면 `needs_shortening` 상태를 표시한다. 계획은 골든 구조·필수 내용·근거 배정에 집중하며 분량 지시는 받지 않는다. 편집자와 편집 코드도 작성자 상한으로 축약·문단 결합을 제어하지 않는다. 중복·연결·학술 문체와 구조·인용 보존 규칙은 유지한다. 분량 설정은 `writing_policy.json`에서 조정한다.

편집의 `join_previous`는 합친 본문이 문단 상한을 넘으면 적용하지 않고 기존 문단 경계를 보존한다. `prevented_paragraph_joins`에 사유를 기록한다. 교체 문장 자체가 긴 경우는 기존 구성 보완으로 돌린다. 화면에서는 600자 안팎의 문장 경계로 긴 평문 문단을 나누며, 단일 긴 문장·코드·수식은 중간에서 끊지 않는다. 이 표시는 본문 축약이나 새로운 내용 검토가 아니다. 표 셀의 장식 그림 이모지를 제거하고 체크·경고 표시는 일반 기호·텍스트로 표시하며, 수치·단위·수식·코드·URL은 보존한다. 저장된 원자료는 변경하지 않는다.

근거 입력이 커서 소절을 여러 요청으로 작성할 때도 **각 요청이 동일한 소절 예산을 나눠 쓴다.** 수정 없이 유지할 문단의 글자 수를 먼저 빼고, 재작성 조각과 누락 내용 보완 조각이 남은 목표를 공유한다. 후보 근거 전체·원문·비교 묶음을 보존하며, 핵심 주장·대표 비교·조건·한계를 우선하고 표의 모든 값이나 후보 사실을 문장으로 열거하지 않도록 지시한다. 편집자에게도 같은 소절별 목표를 전달한다. 별도 요약 에이전트나 길이 전용 재작성 단계는 추가하지 않는다.

분량은 작성 목표이며 새로운 중단 조건이 아니다. `max_tokens`를 낮추거나 본문·JSON·인용을 잘라내지 않는다. 초과한 소절도 기존 내용·형식 검사를 거쳐 보존한다. `writing-length-plan.json`은 소절별 목표, `writing-length-report.json`은 완료 소절의 작성 분량과 최종 편집 분량·초과 여부를 기록한다. 진행 중 실패해도 앞서 완료한 소절 기록은 남는다. 완성된 기록은 `review.json`, `metrics.json`과 화면에서도 확인할 수 있다. 실제 모델의 목표 준수나 API 타임아웃 해소를 보장하는 수치는 아니다.

분량 설정·정책은 작성 실행의 식별자에 포함한다. 목표를 바꾸면 새 폴더에서 작성하며 기존 긴 초안·승인 체크포인트를 덮어쓰지 않는다. 동일한 근거·작성지침·계획 입력에 대한 완료 계획 및 표 배치 응답은 정확한 요청 지문을 확인하고 재사용한다. 동일한 분량으로 다시 실행하면 새 작성 응답도 캐시에서 재사용한다. 이전에 저장한 중단 요청에 분량 설정이 없으면 재개 시 0을 적용해 기존 실행을 이어간다.

## 소절 검토: approved-facts-v1

검토의 `checks`와 `reference_checks` 안에서 같은 `paragraph_ids`가 반복되면 첫 등장 순서를 유지해 동일 ID만 정리한다. 판정·근거 ID·사유는 변경하지 않고 `response_normalizations`에 항목/가이드·제거한 문단 ID·위치를 기록한다. 원래 모델 응답 캐시는 그대로 보존한다. 실제 없는 문단·다른 장 문단은 정리로 숨기지 않고 장·문단 ID를 포함한 오류로 차단한다. 저수준 검증도 중복과 존재하지 않는 문단을 서로 다른 사유로 표시한다.

필수 내용 묶음의 입력 예산은 배열형 논리 스키마가 아니라 실제 전송하는 고정 item/guide 키 스키마(`correction_schema`)와 프롬프트로 계산한다. 형식 보정의 고정 메타데이터도 함께 확인해 기존 장·필수 항목 분할 기준에 반영한다. 상한은 기존 `PAPER_REQUEST_MAX_BYTES`를 유지한다.

검토 형식 보정이 실패한 검토 응답 전체를 다시 붙이면서 예산을 넘는 경우, `review-diagnostics-only-v1`은 그 응답을 원래 validation 파일에 온전히 보존하고 오류 사유·응답 종류·필드별 개수로 보정 피드백을 구성한다. 원래 본문·계획·관련 가이드·승인 범위·선행 근거 검토 요약은 그대로 보낸다. 실패 판정을 met으로 치환하거나 선행 근거 사용 오류를 삭제하지 않는다. `*-correction-input.json`에 전후 바이트·원래 응답 경로·원본 입력 보존 여부를 기록한다. 기존의 유효한 전체 피드백 보정 캐시를 우선 재사용하고 새 형식도 동일 입력이면 재사용한다. 보정은 기존 1회이며, 핵심 입력 자체가 예산을 넘는 경우는 계속 차단한다.

`academic-composition-v2`의 구성 점검은 `composition_length` 외에 `composition_layout`(문단 길이)과 `composition_style`(기록자·자료 중심 표현)을 기존 보완에 연결한다. 단락은 기본 800자 목표를 사용하며 조건·환경·측정·해석을 분리하거나 목록으로 정리한다. 코드·수식·URL 내용은 문체·문단 점검에서 보호한다. 확실성 수준이나 필요한 귀속을 삭제해 학술 문체로 위장하지 않는다. LLM의 기존 근거 검토 역할은 유지하고, 보완 뒤 남은 구성 문제는 본문을 보존한 채 경고로 남긴다. 최종 `composition_quality`는 코드가 확인하는 분량·문단·일부 문체 규칙의 결과이며 독립적인 논문 품질·사실성 보증은 아니다.

공통 정책의 분량 검사는 LLM의 근거 판정과 분리해 코드가 수행한다. 소절 합본·절 편집·전체 편집 후 실제 글자 수가 목표의 허용 비율(기본 125%)을 넘으면 `composition_length` 지적을 기존 보완 요청에 넣는다. 별도 에이전트나 무한 재시도는 추가하지 않는다. 보완 횟수를 소진하면 본문을 보존하고 지적을 경고로 승계한다. 최종 분량 보고서의 `composition_status=needs_shortening`과 화면 메시지는 생성 완료와 분량 목표 달성을 구분한다. 단일 문단으로 합쳐도 총분량 검사를 피할 수 없으며 문단 수와 최대 문단 길이도 최종 기록에 남긴다. 분량 목표 0은 이 분량 검사만 비활성화하며 공통 계획·표·표기 규칙은 유지한다.

입력은 해당 소절의 본문 문단, 작성 계획, 승인된 후보 근거의 statement·조건·수치·한계·주장 성격·사용자 승인 범위다. 근거 원문의 sources.quote, source_elements, 추출 과정의 원문 검토 이력은 보내지 않는다.

- 실제 본문의 주장과 인용한 승인 근거가 맞는지 확인한다.
- 원문 출처·진위는 다시 심사하지 않고 원문 인용문을 생성하지 않는다.
- `required_item.evidence_ids`는 후보 목록이다. 미사용 후보를 실패 이유로 삼지 않는다.
- 필수 내용의 충족 여부는 description과 연결된 작성 기준으로 판단한다. 비교 양쪽의 조건·결과가 필요하면 description에 명시한다.
- 코드의 `used-evidence-scope-v1` 검증은 보고한 사용 근거 ID가 현재 장·소절에 배정됐는지, 선택한 실제 본문 문단에 인용됐는지를 확인한다. 항목별 후보 목록은 사용 근거의 허용 범위를 제한하지 않는다. 표 비교 확장 등으로 소절에 함께 배정된 승인 근거도 실제 인용했다면 보고할 수 있다.
- 항목의 후보 밖에서 실제 사용한 근거는 `used_non_candidate_evidence_ids`에 기록하며 그 사실만으로 실패 처리하지 않는다. 사용했다고 보고한 ID의 본문 인용 누락은 후보 여부와 관계없이 진단한다. 후보 목록이 비었어도 소절에 배정된 실제 인용 근거로 충족을 판정할 수 있으며, 후보·실제 사용 근거가 모두 없는 항목은 확인 필요로 남긴다.
- 모델이 충족으로 판단하고 보고한 사용 근거가 다른 실제 문단에 인용돼 있으면, 코드가 그 문단 ID를 검토 기록에 연결한다. 본문·인용·판정은 바꾸지 않고 별도 모델을 호출하지 않는다.
- 실제 인용도 없거나 내용·근거 연결이 잘못됐으면 해당 작성자가 수정한다.

작은 소절은 승인 근거 사용과 필수 내용을 함께 검토한다. 입력이 크면 기존 분할 검토에서 본문 문단과 실제 사용 근거를 예산 안에서 대조한다. 이때 statement·수치·조건·한계 정보를 유지하며 원문 자체를 재검증하지 않는다. 모든 실제 문단/인용 ID가 검사 범위에 포함됐는지 코드로 확인한다.

큰 입력의 이후 필수 내용 검토는 `content-coverage-v2` 정책을 사용한다. 전체 소절 본문, 해당 필수 내용 description, 관련 작성지침과 사용자 승인·제외 범위, 선행 근거 사용 검토 요약만 전달한다. 개별 facts·표·추출 이력·다른 질문의 상태·계획 보정 이력은 반복 전송하지 않는다. 필수 내용은 본문에 실제 비교 대상·결과·조건 등이 있는지 판단하며, 앞 단계에서 대조한 출처·수치·한계를 다시 검증하지 않는다. JSON 보정 요청도 같은 역할 범위를 유지한다.

사용자 지시가 다른 소절에만 연결됐다는 근거가 있는 경우에만 제외한다. 연결이 없는 제외·제한 지시와 현재 소절에 적용되는 임시 승인·부족 필드는 유지한다. 선행 근거 사용 검토의 지적은 코드가 원래 사유·근거·문단과 함께 별도 보존하며 최종 보고서에 합친다. 필수 내용을 met으로 판정해도 선행 오류를 승인으로 바꾸지 않는다.

## 절·전체 편집 검토: editorial-v1

고정 구간 편집의 최초·보완 요청은 전체 문맥·출력 스키마·지침을 포함한 실제 요청 크기를 `PAPER_REQUEST_MAX_BYTES`(기본 240,000바이트)와 비교한다. 이 경로에는 실패 응답 복사를 위한 일괄 25% 예비 공간을 적용하지 않는다. 다른 작성·검토 입력 묶음의 보수적 75% 패킹 정책과 API 대기 시간은 바꾸지 않는다. 이는 UTF-8 바이트 기반 프로젝트 예산이며 공급자 토큰 한도나 응답 시간 보장은 아니다.

편집 형식 보정은 동일한 전체 본문·목차·기존 검토 지적을 유지하고 오류 사유·지목된 구간 ID·소절 보호 범위를 전달한다. 실패 응답의 본문 전체를 다시 넣지 않는다. 원래 실패 응답은 기존 invalid/native 기록에 보존한다. `*-repair-input.json`에 전체 문맥 유지 여부, 원래 오류 기록과 축소한 피드백의 크기, 최종 요청 크기를 기록한다. 예전 전체 실패 응답을 포함한 완료 보정 캐시도 본문·고정 구간 검증을 통과하면 재사용한다. 실제 상한을 넘는 최초·보정 요청은 API 전송 전에 중단하며 본문을 자르지 않는다.

편집자는 중복 문장·문단을 줄일 수 있지만 장·소절 전체를 삭제할 수 없다. 각 소절의 목적·핵심 설명·조건·한계를 남겨야 하며, 다른 소절과 겹쳐도 현재 소절의 역할에 맞게 압축한다. 분량 목표보다 구조와 핵심 내용 보존이 우선한다.

고정 구간 편집 결과가 소절 전체 삭제라면 코드는 해당 장·소절·제목을 보정 요청에 명시한다. 보정 1회 후에도 전체 삭제가 반복되면 그 소절의 편집만 취소하고 직전 본문·인용을 그대로 보존한다. 다른 소절의 유효한 수정은 유지한다. 이 보호는 최초 편집·보완, 절·전체 편집, 여러 묶음에서 누적된 삭제 모두에 적용한다. 알 수 없는 ID·출력 칸 누락 등 다른 형식 오류를 이 방식으로 통과시키지는 않는다.

원래 삭제 응답과 보정 응답은 보존하고 편집 provenance의 `preserved_subsections`에 취소 사유를 기록한다. 최종 검토·검토 경고 모음에는 `subsection_removal_prevented` 경고를 남긴다. 체크포인트 재개·완성 초안 재로드 시에도 경고를 유지한다. 기존 정상 편집 응답 캐시는 새 지침을 보내기 전에 검증·재사용한다.

입력은 목차·절 목적과 실제 본문 문단뿐이다. 연구 근거·원문·필수 근거 목록은 전달하지 않는다.

- 1차 편집 검토: 소절 간 중복, 문단 연결, 설명 순서, 용어·문체의 일관성.
- 2차 편집 검토: 절 간 중복, 전체 흐름, 서론·결론의 호응, 글의 통일성.
- 응답은 duplication / flow / organization / terminology / style 유형의 issues만 받는다. 내용·근거 심사를 위한 checks나 source_quote를 요청하지 않는다.
- 하위 소절에서 완료한 내용·지침 검토 결과는 기록으로 승계한다. `required_content_coverage`와 `reference_application`에는 `rechecked=false`와 승계 범위를 표시한다. 최종 본문을 다시 사실 검증했다는 의미가 아니다.
- 같은 필수 항목이 여러 소절의 호환 입력에 반복돼도 승계 충족률에서 중복 계산하지 않는다.

큰 본문은 인접 문단을 겹쳐 나누어 모든 문단·인접 연결이 편집 검토에 포함되도록 한다. 단일 문단이나 인접 문단 쌍 자체가 입력 예산을 넘으면 자르거나 검토를 생략하지 않고 중단한다.

편집 보완 후 재검토는 `editorial-recheck-v3`로 입력을 구성한다. 현재 본문 창은 인접 문단을 겹쳐 유지하고, 각 창에 포함된 절의 기존 지적을 입력 예산 안의 묶음으로 배정한다. 이전 문단 ID는 편집 중 삭제·통합·재번호화될 수 있으므로 현재 ID 목록과 다르다는 이유로 지적을 제외하지 않는다. 기존 오류·경고의 사유와 판정은 그대로 보내며, 같은 이전 문단의 같은 인용문은 previous_paragraphs에 한 번만 보관하고 지적에서는 quote_ref로 참조한다. 이 인용문은 이전 초안 문단이며, 기존 지적의 해결 여부를 대조하는 문맥이다. 연구 근거의 원문 검증을 추가하지 않는다.

`review-*-editorial-recheck-v3-input.json`에는 원래 지적·인용문과 현재 본문, 묶음별 문단·지적 ID·입력 크기와 지적 배정 개수를 저장한다. 모든 이전 지적이 하나 이상의 입력에 배정됐는지 코드가 확인한다. 모델은 `findings`의 지적 ID별 고정 칸에 `status`(resolved/unresolved/not_assessable)와 현재 `paragraph_id`만 반환한다. 장·문제 유형·심각도·긴 사유는 다시 생성하지 않으며 코드가 원래 지적에서 가져온다. 한 지적을 여러 문제로 늘리거나 다른 지적 ID·장 문단을 반환하지 못하도록 스키마와 코드에서 검사한다. 입력 예산에는 이 실제 응답 스키마도 포함한다.

한 지적이 여러 본문 창에 배정되면 미해결 응답이 하나라도 있는 경우 원래 지적 하나를 유지한다. 확인 불가만 반환된 지적도 해결된 것으로 올리지 않으며 기존 오류·경고 수준을 유지하고 기존 편집 보완 횟수 정책을 따른다. `*-results.json`에 지적별 상태와 미해결 개수를 기록한다. 정상 완료된 v2 및 더 이전 재검토 응답은 캐시 전용으로 확인해 재사용하고 원본 기록은 덮어쓰지 않는다. 신규 v3 묶음 응답도 중단 후 재개 시 재사용한다. 입력 상한과 검토 기준은 유지한다. 본문과 단일 지적 자체가 들어가지 않으면 `*-budget-failure.json`에 본문·이력 크기를 분리해 기록하며, 큰 이력을 작은 문단의 크기 문제로만 표시하지 않는다.

## 수정과 기본 검증

실제 문제를 발견하면 해당 단계의 작성자 또는 편집자만 수정한다. 소절은 최초 작성과 내용 수정 최대 2회, 각 시도에서 형식 보정 최대 1회를 허용한다. 검토 응답의 JSON·ID 오류도 본문을 바꾸지 않고 응답 형식만 최대 1회 보정한다.

소절의 내용 보완 2회를 모두 사용한 뒤 남은 내용·근거 사용·필수 내용 지적은 `content-warning-v1` 정책으로 warning에 남기고 편집 단계로 진행한다. 원래 사유와 error 심각도는 `original_severity`·`deferred`로 보존하며, 원본 검토 응답도 체크포인트에 남긴다. `approved=true`는 다음 단계로 진행 가능하다는 뜻이다. `content_approved=false`, `content_status=needs_attention`, `content_warnings`로 미해결 내용을 구분한다. missing/incorrect 판정과 충족률은 충족으로 바꾸지 않으며, 없는 인용을 추가하지 않는다. 응답 형식·ID·무결성 오류와 확인할 수 없는 검토 메타데이터는 이 정책으로 완화하지 않는다.

큰 소절을 분할 수정할 때의 `missing_evidence` 요청도 누락 근거를 포함하도록 1회 보정한다. 보정 응답의 본문·실제 인용 ID가 유효하고 요청 근거 일부만 계속 빠졌다면 `fragment_missing_evidence` 경고로 남겨 전체 소절 검토를 계속한다. 빈 본문·잘못된 형식·없는 ID·배정 범위 밖 인용은 계속 차단한다. 실제 근거 ID를 임의로 덧붙이지 않는다. 조각별 `*-content-warning.json`과 분할 manifest에 보정 횟수·누락 ID를 저장하며, 완성한 소절의 `generation_warnings` 체크포인트와 최종 `review-warnings.json`에도 승계한다. 다른 조각이나 다음 보완에서 해당 ID가 실제 인용되면 현재 경고에서 제거한다. 기존 누락 응답과 보정 요청의 입력·식별자는 유지해 저장된 응답을 재사용한다.

분할 보완 입력이 예산을 넘으면 `fragment-revision-context-v1`으로 피드백 문맥을 좁힌다. 현재 source_body 문단의 지적과 문단 지정이 없는 공통 지적을 유지하며, 다른 문단에 배정된 지적은 그 문단의 별도 요청에 둔다. 누락 내용 추가 요청은 기존 문단의 지적을 반복 전송하지 않는다. 지적의 quote가 이미 전달한 source_body와 정확히 같을 때만 중복을 제거하고, 별도 대조 구절·원래 지적 사유는 보존한다. 근거 statement·원문·조건·수치·한계, 비교 표와 사용자 승인·제외 내용은 그대로 유지한다. 예산 안의 기존 입력은 이 정책으로 변경하지 않아 완료 응답 캐시를 계속 재사용한다. 적용한 범위는 요청의 revision.scope와 분할 manifest에 기록한다. 비교 묶음과 입력 예산은 유지하며, 중복 문맥 제거 후에도 크면 계속 중단한다.

절·전체 편집은 최초 검토 후 기존 지적을 대상으로 최대 2회 보완한다. 신규 최초 1·2차 편집은 `editorial_patch.py`의 `editorial-assembly-fixed-spans-v1` 형식을 사용한다. 전체 본문과 장·소절 목적·필수 내용 설명을 읽고 중복 제거·문단 연결·용어 통일에 필요한 구간만 수정한다. 근거 원문·추출 이력은 입력하지 않는다. 응답은 `sections → 장 → parts → 소절 → 기존 구간`의 고정 칸이며 action=keep/replace/delete, text, join_previous만 받는다. keep/delete는 본문을 다시 출력하지 않고 빈 text를 반환한다. 문단 첫 구간만 같은 소절의 앞 문단과 합칠 수 있고, 장·소절·구간 순서는 코드가 유지한다. 문단·spans 래퍼를 반복하지 않아 긴 절의 출력 스키마 크기도 줄인다.

최초 편집은 보완 단계와 같은 적용·인용 승계 검증을 사용한다. 전체 문맥을 보존하며 입력 예산을 넘으면 요청 전에 중단한다. 이 변경은 전체 본문 재출력 부담을 줄이며 Solar 서버·네트워크의 응답 지연 해소를 보장하지 않는다. 기존 `editorial-provenance-v2`의 완료 응답은 캐시 전용으로 대조해 유효하면 재사용한다. 캐시가 없거나 실패한 요청은 구형 전체 재출력 API를 다시 호출하지 않고 새 형식으로 보낸다. 기존 정상 승인 체크포인트와 보완 단계의 요청 식별자는 유지한다.

최초 편집이 24개 구간 또는 편집 대상 본문 24KB를 넘으면 `editorial-assembly-batches-v1`으로 편집할 출력 칸만 묶는다. 각 요청은 전체 source_parts를 읽지만 editable_spans의 고정 칸만 반환한다. 단일 원문 구간을 자르지 않으므로 큰 단일 구간은 단독으로 처리한다. 앞 묶음의 유효한 수정은 다음 요청의 전체 문맥에 반영하며, 삭제 구간도 식별자와 삭제 상태로 표시한다. 다른 묶음의 읽기 전용 칸을 출력하면 형식 보정 대상이다. 묶음별 응답은 캐시에 남기고, 진행 기록은 `*-editorial-assembly-batches-v1-progress.json`에 저장한다. 모든 묶음이 완료돼야 결과를 해당 단계 검토로 넘긴다. 중간에 시간 초과가 나면 완료 응답을 재사용해 남은 요청부터 재개한다. 기존 고정 칸 v1의 유효한 완료 응답도 우선 재사용한다. 작은 최초 편집 요청과 검토 후 보완의 정책은 유지한다.

큰 편집 보완 또는 기존 전체 보완 요청이 입력 예산을 넘는 경우에는 `editorial-revision-batches-v1`을 사용한다. 전체 최신 본문을 유지하고, error 지적의 대상 문단·사유에서 명시한 실제 문단·앞뒤 문단의 구간만 편집 대상으로 배정한다. 문단 지정이 없는 오류는 해당 절 전체에 적용한다. 각 묶음에는 배정 구간과 관련된 오류 지적만 전송한다. 경고는 원래 검토 이력과 진행·출처 연결 기록의 deferred_warnings에 보존하고 보완 요청에 반복 전송하지 않는다. 오류의 사유를 자르거나 충족으로 바꾸지 않는다. 앞 묶음 수정 반영, 고정 칸·인용 검증, 묶음별 캐시 재개와 전체 완료 후 검토 원칙은 최초 편집과 같다. 작은 기존 보완 요청과 유효한 기존 완료 응답의 캐시는 유지한다. 전체 본문 자체가 여전히 예산을 넘으면 요청 전에 중단하며 `*-budget-failure.json`에 입력 크기·문맥 크기·적용 지적 수를 남긴다.

작은 검토 후 보완은 `editorial_patch.py`의 `editorial-fixed-slots-v1` 형식을 사용하고 큰 보완은 위의 묶음 형식을 사용한다. 현재 편집 단계의 전체 본문과 목차·목적·해당 지적을 전달하고, 코드가 기존 장·소절·문단·인용 구간에 대응하는 출력 칸을 스키마에 고정한다. 편집자는 배정된 고정 칸을 채우되 유지할 구간의 원문을 다시 출력하지 않고, 수정할 구간의 새 문장만 출력한다. 기존 지적에 이미 본문 문단 ID가 연결되어 있으므로 긴 인용문을 지적마다 중복 전송하지 않는다. 전체 문맥 자체가 입력 예산을 넘으면 문맥을 자르거나 일부를 적용하지 않고 요청 전에 중단한다. 출력 부담을 줄이는 변경이며 Solar 서버·통신 지연이나 300초 시간 초과 해소를 보장하지는 않는다.

편집자는 근거 ID를 입력받거나 반환하지 않는다. 코드는 기존 문단을 인용 표시 위치에서 구간으로 나누고 각 구간에 식별자를 부여한다. 편집 요청의 `source_parts`에는 구간 ID·원래 문단 ID·인용 표시를 뺀 본문만 들어가고 기존 근거 ID 연결은 코드 내부에 보관한다. 동일한 본문이 반복돼도 원래 위치별로 다른 ID를 부여한다.

구형 `editorial-provenance-v2`의 캐시 재생은 기존 segments/source_id 연결을 그대로 검증한다. 신규 최초 편집의 고정 구간 키는 코드가 문단 칸으로 확장한 뒤 같은 보완 적용기에 전달한다. 각 구간 뒤에는 그 구간의 기존 인용만 붙이며 여러 출처를 문단 끝에 일괄 합치지 않는다. 삭제한 구간의 인용은 추가하지 않는다. 잘못된 고정 칸·배정 밖 인용·본문 형식 오류는 계속 차단한다.

보완 출력은 `sections → 장 ID → parts → 소절 칸 → 기존 문단 ID → spans → 기존 구간 ID` 경로가 코드에서 고정된다. 이 키들은 선택 가능한 ID 목록이 아니라 반드시 한 번씩 채워야 하는 고정 필드다. 각 구간은 `action=keep/replace/delete`와 `text`만 반환한다. keep은 원문·인용 유지, replace는 해당 구간의 문장만 수정, delete는 해당 구간과 인용 삭제다. keep/delete의 text는 빈 문자열을 권고하며, 내용이 들어 있어도 동작을 바꾸지 않고 무시한다.

편집자가 `section_id`, `part`, `paragraph_ids`, `replacement`, `source_id` 값을 따로 지정하는 필드는 없다. 다른 소절의 구간 키는 해당 출력 칸의 스키마에 존재하지 않는다. 코드가 원래 순서·위치·인용을 적용하므로 수정 범위와 출처 범위를 모델이 서로 맞출 필요가 없다. 필요한 인접 구간도 그 구간의 고정 칸에서 수정한다. 문단의 `join_previous=true`는 같은 소절 안의 앞선 유지 문단과 합친다. 소절 첫 문단에서는 앞 소절과 합치지 않고 그대로 둔다.

변경하지 않은 본문과 인용은 원래 문자열 그대로 보존한다. 문단 통합 후에도 각 구간 뒤의 인용은 분리해서 유지한다. 고정 칸이 누락·추가되거나 직접 인용 표시·잘못된 본문이 출력되거나 소절 본문을 모두 지우면 형식 보정 대상이다. 하나라도 잘못되면 부분 수정 결과를 적용하지 않는다. 합쳐진 전체 절·논문은 기존 편집 지적의 재검토에 전달한다.

기존 한 구간에 근거 ID가 여러 개 붙어 있었다면 그 인용 묶음은 유지한다. 코드는 일부 요약 문장의 의미를 판단해 그중 특정 ID를 삭제하거나 새 ID를 추정하지 않는다. 따라서 이 연결은 기존 인용의 추적을 보장하는 것이며 수정 문장의 사실성이나 의미 보존을 자동으로 입증하지 않는다. 새로운 사실·수치·실험을 추가하지 않고 기존 조건·한계·사용자 승인 범위를 유지하는 것은 편집자의 지침이다.

코드는 보완 전후 본문과 지적 문단의 변경 여부를 기록한다. 공백·인용 표시만 바뀌거나 본문이 그대로면 동일 본문의 모델 재검토를 생략하고 다음 보완 요청에 변경 없음 사실을 알린다. 본문이 바뀌면 검토자에게 이전 지적·이전 문단과 현재 본문을 전달해 기존 지적의 해결 여부만 재확인한다. 삭제·통합으로 문단 번호가 바뀔 수 있으므로 이전 번호가 현재 번호와 같다고 가정하지 않는다. 새 문제 유형·다른 장의 지적을 추가한 재검토는 응답 형식 보정 대상으로 처리한다.

2회 보완 후에도 남은 편집 문제는 원래 error 판정과 보완 이력을 보존하며 warning으로 남기고 다음 단계로 진행한다. `approved=true`는 진행 가능한 초안이라는 의미이고, `editorial_status=needs_attention`과 `editorial_warnings`가 편집 확인 필요 사항을 별도로 표시한다. 하위 소절의 내용 경고와 절의 편집 경고는 전체 검토 기록과 UI에도 승계하며, 상위 단계에서 새로 해결 확인한 것으로 간주하지 않는다.

없는 근거 ID, 소절 범위 밖 인용, 없는 문단, 장·본문 칸 누락, 제목·표 직접 생성, 체크포인트 해시 불일치는 코드로 계속 차단한다. 편집 문제는 해당 문단·편집 단계로 되돌리고 소절 내용 검토를 다시 실행하지 않는다.

현재 실행·다른 모드·CLI·평가 도구에서 호출하지 않는 과거 원문 지적 재심사·별도 인용 보정·모델 문단 선택 보정 코드는 제거했다. 현재 작성자의 내용 수정, 코드의 기존 인용 연결, 검토 JSON 형식 보정과 재개 처리는 유지한다. 제거한 기능 자체의 테스트는 정리하고 현재 작성·검토·재개 동작을 검사하는 회귀 테스트는 유지한다.

## 저장과 재개

각 단계는 `workflow/subsection-<id>-p<n>`, `workflow/section-<id>`, `workflow/paper`에 저장한다.

- responses/: 개별 모델 응답·호출 캐시
- candidate.json: 후보 본문과 현재 검토 결과
- reviews.json: 해당 단계의 검토·수정 이력
- review-*-evidence-usage.json: 큰 입력의 근거 사용 대조 묶음·완료 범위·원래 지적. 필수 내용 검토 이전에 저장
- generate-*-editorial-provenance-v2-provenance.json: 최초 편집의 출력 구간별 출발 문단·기존 인용 연결
- generate-*-editorial-assembly-fixed-spans-v1-provenance.json: 신규 최초 편집의 고정 칸별 수정·삭제·문단 통합과 기존 인용 연결
- generate-*-editorial-assembly-batches-v1-progress.json, *-provenance.json: 큰 최초 편집의 완료 묶음·고정 칸과 최종 인용 연결
- generate-*-editorial-revision-batches-v1-progress.json, *-provenance.json: 큰 편집 보완의 완료 묶음·경고 보존·고정 칸과 최종 인용 연결
- generate-*-editorial-fixed-slots-v1-changes.json: 보완 전후 변경된 본문 칸과 그대로 남은 지적 문단
- generate-*-editorial-fixed-slots-v1-provenance.json: 보완 전후 본문 해시, 고정 칸별 수정·삭제, 인용 연결과 문단 통합 기록
- approved.json: 입력 식별자·본문·검토를 묶은 승인 체크포인트
- checkpoint-history/: 이전 승인과 정책 전환 기록 보존
- review-*-diagnostics.json, failure-details.json/md: 실제 본문·근거 사용 또는 편집 지적의 진단 기록

실행 폴더의 `review-warnings.json`은 완료한 단계의 내용·편집 경고를 한곳에 모은다. 단계 ID·소절 제목·지적·보완 횟수·원래 검토 이력 경로와 당시 본문·근거·원문 위치·사용자 승인 정보를 포함한다. 각 단계가 완료될 때 갱신하므로 후속 API 요청이 중단돼도 앞선 경고를 확인할 수 있다. 본문 스냅샷은 해당 단계 검토 당시의 내용이며 최종 편집 본문을 다시 검증한 결과가 아니다. UI의 **검토 경고 모음**에서 지적을 모아 보고 JSON을 내려받을 수 있다.

경고를 남긴 소절도 `content_completion`이 포함된 체크포인트로 저장한다. 재개 시 본문·ID·원본 검토의 기본 검증과 완료 정책을 다시 확인한 뒤 재사용하며, 내용 경고만으로 같은 소절을 계속 재작성하지 않는다.

새 검토 정책은 개별 요청에 반영해 이전 원문 대조·지적 재심사 실패 캐시를 재사용하지 않는다. 편집의 구간 추적 요청과 고정 칸 보완도 별도 이름·스키마·정책을 사용해 이전 evidence_ids 응답 실패, 전체 재출력의 시간 초과, edits 범위 불일치 요청과 구분한다. 보완 요청의 `base_fingerprint`는 인용을 포함한 원래 본문에 결속되어 다른 버전의 본문에 오래된 수정을 적용하지 않는다. 계획·작성 입력 식별자는 유지한다. 승인된 소절 본문은 기본 검증 뒤 재사용하며, 기존 정상 편집 승인도 재사용한다. 이전 통합 근거 검토로 승인된 절·전체 본문은 재작성하지 않고 새 편집 검토만 수행한다. 수정된 하위 본문으로 편집 입력이 달라지면 해당 상위 편집만 다시 수행한다.

`content-coverage-v2`는 필수 내용 요청의 이름·입력·프롬프트만 구분한다. 이미 완료한 근거 사용 대조 요청의 입력·프롬프트는 유지하므로 동일 본문의 대조 응답을 재사용한다. 본문·사용 근거가 바뀐 대조 요청은 기존 캐시에 해당하지 않는다. 입력이 여전히 예산을 넘으면 포함된 본문·기준·승인 범위가 크다는 사유로 중단하고, 논문 구조를 자동으로 나누지는 않는다.

본문 구조·인용 ID 검증을 통과하고 소절 내용 검토와 편집 검토가 각각 완료 또는 보완 후 경고를 남긴 상태가 되어야 draft.md와 마지막 초안 포인터를 갱신한다. 형식·인용·무결성 오류나 전송 중단은 이전 초안을 유지한다. 중단·수정 후보와 원래 응답은 보존한다. 모델의 의미 판단과 코드의 단순 본문 변경 감지는 실제 편집 품질이나 저자의 검토를 대체하지 않는다.

JSON 저장은 같은 폴더의 임시 파일을 완성한 뒤 대상 파일로 교체한다. 파일 잠금·접근 거부가 발생하면 같은 임시 파일로 최대 5번, 총 대기 1.5초 범위에서 교체를 시도한다. 계속 실패하면 기존 대상 파일과 완성된 임시 JSON을 유지하고 오류에 임시 경로를 표시한다. 읽기 전용 속성을 강제로 바꾸거나 기존 파일을 지운 뒤 덮어쓰지 않는다.

Solar의 `.native.request.json` 진행 기록과 전송 실패 진단은 보조 기록이다. 이 저장이 실패하면 경고를 기록하고 응답 처리·정상 캐시 저장을 계속한다. HTTP 응답을 받은 뒤에는 응답 원본을 먼저 저장하고 진행 기록을 갱신한다. 응답 원본이나 정상 캐시 같은 핵심 저장이 계속 실패하면 임시 데이터를 보존한 채 중단하며, 정상 완료로 처리하지 않는다. 저장 재시도는 API 재호출과 별개다.

`PlannedPaper`의 공통 Solar 전송 정책은 기본적으로 시간 초과·연결 실패 시 같은 실행 안에서 1초 뒤 동일한 요청을 한 번 자동 재전송한다. 계획·작성·편집·검토 단계에 공통으로 적용하며, 명시적인 transport_retries=0 호출은 재전송을 끌 수 있다. 첫 전송이 성공하면 재전송하지 않는다. 재전송도 실패하면 그때 오류를 반환하며, 응답을 받지 못한 요청을 완료 캐시로 기록하지 않는다. HTTP 오류·본문/ID 검증 오류는 이 정책으로 재시도하지 않는다. 기존 JSON 응답 형식 보정은 별도 정책으로 유지한다.

이 정책은 요청 내용·묶음·입력 상한·캐시 식별자를 바꾸지 않는다. 이미 완료한 응답은 API 전송 없이 먼저 재사용하며, 새로 전송할 요청부터 기본 자동 재시도를 적용한다. 각 전송 시도와 실패·성공 기록은 `.native.request.json` 및 개별 transport-error 파일에 보존한다. 사용자 지정 client는 해당 client가 전송을 관리하며, 공통 계층에서 임의로 중복 호출하지 않는다.
