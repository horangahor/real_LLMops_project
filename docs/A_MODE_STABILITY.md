# A 모드: 질문 기반 근거 수집의 재개 처리

A 모드는 앱의 `작성지침 → 요구사항 → 근거` 경로(`evidence_mode="requirements"`)다. 골든 지침에서 만든 공통 질문에 따라 연구 일지를 읽고, 원문 검증과 질문별 충족 판단 및 사용자 결정을 거쳐 작성 입력을 만든다. 전체 수집 모드의 정책은 사용하지 않는다.

## 페이지 수집 체크포인트

실행 폴더의 `collection-progress.json`은 `requirement-page-progress-v1` 형식으로 다음을 저장한다.

- `completed_page`: 마지막으로 처리를 끝낸 페이지. 성공·보류 여부는 아래 목록과 구분한다.
- `raw_items`: 해당 시점까지의 근거 ID·내용·조건·측정·원문 ID·질문 연결
- `scanned_pages`: 실제 추출 대상 원문이 있는 처리 페이지
- `pending_pages`: 응답·출처·연결 검증에 실패해 보류한 페이지
- `applicability`: 완료한 질문 적용 여부 판단
- 현재 원문·질문·기존 추출 지침의 입력 해시와 체크포인트 내용 해시

페이지 응답을 검증하고 반영한 뒤 원자적으로 저장한다. 응답을 받지 못하면 마지막 저장 상태를 유지한다. 다음 실행은 저장 상태를 검증한 뒤 다음 페이지부터 시작하며, 완료한 적용 여부 판단과 페이지 응답을 재생하지 않는다. 수집 완료 후 원문 검토 도중 끊겼을 때도 페이지 수집 전체를 다시 순회하지 않는다. 원문 검토의 개별 완료 응답은 기존 API 캐시를 사용한다.

원문이 없는 페이지와 보류된 페이지를 성공 근거로 바꾸지 않는다. 원문 검토 및 질문 충족 검사도 생략하지 않는다. 전체 페이지 수집이 끝났다는 사실만으로 `ready_for_drafting`을 열지 않는다. 기존의 필수 질문 부족·적용 미확인·미해결 원문 게이트는 유지한다.

## 이전 결과와의 호환

`assessment-input.json`이 있으면 기존 질문 검토·사용자 결정 재개 경로를 우선 사용한다. 새 페이지 체크포인트를 위해 기존 수집 결과나 작성용 근거를 다시 만들지 않는다. 실행 폴더의 입력 해시 계산도 바꾸지 않아 기존 완료 실행을 같은 경로에서 찾는다.

원문 또는 질문이 달라지면 별도 실행 폴더를 사용한다. 체크포인트의 해시·진행 범위·질문 적용 판단·근거 ID·처리 페이지 밖 출처가 맞지 않으면 모델 호출 전에 중단한다. 잘못된 상태를 자동 승인하거나 새 상태로 덮어써 진행하지 않는다.

사용자 제외·임시 승인 기록, 조건·수치·한계, 탈락 후보의 격리 정책에는 변경이 없다. 원문 검토 이전의 raw 근거와 작성용으로 검증된 근거는 계속 구분한다.

## 검증 범위

`tests/test_requirement_collection_progress.py`에서 페이지 전송 중단과 원문 검토 중단을 주입해 확인한다.

- 완료 페이지와 적용 판단의 재호출 없이 다음 페이지부터 재개
- 동일 사실의 두 페이지 출처 및 여러 질문 연결 유지
- 보류 페이지가 재개 후에도 초안 생성을 차단
- 손상된 해시·잘못된 페이지 범위·미처리 페이지 출처 차단
- 원문/질문 변경 시 새 수집 시작
- 기존 질문 검토 체크포인트 우선 재사용

이 검증은 재개 처리에 관한 것이다. 모델의 새 추출 품질이나 실제 전체 실행 시간 개선을 측정한 것은 아니다. 페이지 요청에 누적 근거를 전달하는 기존 방식의 경량화는 별도 검증이 필요하다.
