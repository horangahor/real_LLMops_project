# 작성 검토 실패: subsection-evaluation-p1

## 검토 지적

- [원문·내용 검토; 처리 책임: writer] E00081(mempool + warmup + 결과 벡터 memcpy 제거 후 16개 출력값 기록)을 근거로 사용했으나, 해당 문단에는 실행 시간 수치가 포함되어 있지 않다. 문단의 'warmup, 결과 벡터 memcpy 제거, forward 함수의 DTOH memcpy 제거가 적용되면서 실행 시간이 64.716000 ms까지 감소하였다'는 주장은 E00083(64.716 ms)과 연결되어야 하며, E00081은 출력값 기록 근거로만 써야 한다. 현재 근거 목록과 서술이 잘못 연결되어 있다.
  - 문단: evaluation_p1; 근거: E00081, E00083
  - 실제 본문: 최적화 과정은 단일 GPU 가속 시도에서 시작해, 연산 일부만 GPU로 옮기는 하이브리드 구성과 메모리·커널·호출 경로 개선을 차례로 적용하는 방식으로 진행되었다. 초기 GPU OPTIMIZED 모드 이후에도 CPU보다 느렸기 때문에 행렬곱만 GPU로 실행하는 하이브리드 프로그램을 시도했고, 그 결과 CROWN 검증 실행 시간이 201.670100 ms로 기록되었다. 이후 HYBRID V2에서는 85.785300 ms로 줄어 기록자가 CPU보다 빨라졌다고 평가했다. 메모리 풀과 가중치 사전 업로드(PRELOAD ON GPU)를 함께 적용한 모드에서는 149.820400 ms가 관측되었고, 기록자는 이를 149~155 ms 범위로 요약했다. 다만 bias까지 GPU에 미리 올리는 시도는 벡터 크기가 약 4 KB 정도로 작아 CPU 연산 부담이 크지 않다고 판단되어, 성능 개선 의미가 크지 않은 것으로 해석되었다. 이후 warmup, 결과 벡터 memcpy 제거, forward 함수의 DTOH memcpy 제거가 적용되면서 실행 시간이 64.716000 ms까지 감소하였다. 한편 cudaHostRegister(Pinned)와 No Pinning을 92만 번 루프에서 비교한 결과 전체 시간은 787.88초 대 776.70초로 약 1.4%(약 11초) 차이에 그쳤고, 1회당 약 12 μs 수준의 미세한 차이였다. 단계별로 보면 Bound 단계(전체 85%)에서는 cudaHostRegister가 658.80초로 No Pinning의 663.17초보다 4.37초 빨랐으나, Infer 단계(전체 15%)에서는 cudaHostRegister가 127.18초로 No Pinning의 111.92초보다 15.26초 느려져 역전되었다. 이 역전 현상에 대해 기록자는 추론 단계에서 시간이 느려졌다고 관찰했고, 컴퓨터 구조와 GPU 드라이버 레벨에서 3가지 기술적 이유가 있다고 남겼다. 이후 GPU 클록을 2800 MHz로 고정해 재실험을 시도했으며, 클록 확인·고정에는 nvidia-smi 명령어와 Persistence mode 설정이 사용되었다. 이러한 최적화 단계별 변화는 실행 시간을 줄였지만, 각 기법의 효과가 분리된 단일 실험으로 정리된 것은 아니며, 여러 변경이 함께 적용된 상황에서 개별 기여도는 제한적으로만 해석할 수 있다.
