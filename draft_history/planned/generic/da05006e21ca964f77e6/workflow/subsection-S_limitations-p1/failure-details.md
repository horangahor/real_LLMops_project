Pinned Memory는 데이터가 충분히 클 때 빠르다는 전제 조건이 있으며, 1,028 Byte(1 KB) 수준에서는 No-Pin(일반 메모리)이 더 빠를 수 있는데, 이는 CPU L1 캐시에서 드라이버 내부 버퍼로 복사하는 데 불과 20~30 나노초(0.00003 ms)면 끝나는 반면, Pinned Memory는 PCIe DMA 엔진에 명령 패킷을 쏘고 트랜잭션을 시작하는 하드웨어 오버헤드만 약 1~2 마이크로초(0.0015 ms)가 걸려 작은 데이터에서는 DMA 셋업 오버헤드가 누적되어 infer 단계에서 정확히 13초(132초 vs 119초)가 더 걸린 사례가 있었다는 서술도 측정 블록과 함께 제시된다. 구성 요소별 역할로는 cuBLAS는 NVIDIA GPU에서 선형대수 연산을 가속하는 라이브러리이며, 메모리 풀은 함수 호출마다의 메모리 할당·해제를 없애기 위해 큰 공간을 미리 할당해 빌려주는 방식으로 사용되고, 가중치(W) GPU 사전 업로드는 고정된 가중치를 네트워크 로드 시점에 미리 GPU에 올려 matmul 호출마다의 memcpy를 줄이려는 역할이며, 벡터 연산을 CPU로 돌리는 것은 matmul만 GPU로 실행하는 하이브리드 구성을 만들기 위한 역할로 설명된다. 결합 방식은 초기에는 cuBLAS로 matmul을 대체하고 메모리 풀을 사용하며 벡터 연산을 CPU로 돌리는 GPU 최적화 모드(MODE: GPU OPTIMIZED (cuBLAS + Pool))로 결합되었다가, 이후 matmul만 GPU로, 나머지를 CPU로 처리하는 하이브리드 모드(MODE: HYBRID (matmul=GPU, rest=CPU))로 바뀌었고, v2 적용 방안에서는 cuBLAS 예열(더미 matmul 호출로 초기화), 가중치 GPU 사전 업로드, 16×491 행렬 등 필요한 부분만 복사하도록 memcpy 범위를 줄이는 방식이 추가로 결합되었다고 기록된다. forward+backward 결합은 정방향과 backward 바운드를 함께 실행하는 방식으로 측정되며, backward_only는 backward 바운드만 실행하는 방식으로 측정되고, CUDA 그래프(cudaGraph) 적용 버전도 별도로 측정된다. backward_only가 forward+backward보다 빠르게 관측되었고, forward가 가장 느리게 관측되었으며, 이는 일반적인 예상(forward < forward+backward < backward_only)과 다른 실행 결과로 기록되었다. CUDA 그래프 적용 후 전체 소요 시간이 감소하였고(예: 787s → 630s, 1029s → 668s), Phase breakdown에서 bound 단계가 전체 elapsed의 대부분을 차지하고 infer 단계가 그 다음, certify 단계가 가장 작은 비중을 차지한다는 관측도 함께 제시된다. 구성 요소별 역할로 pinned Memory 추가, cudaEvent 제어, 필요한 만큼 계산해서 D2H memcpy, certify topk 자료구조 스택화가 각각 언급되지만, 구성 요소들의 결합 방식은 실제 구현·실행 원문에서 직접 기술된 결합 구조나 연결 방식이 확인되지 않는다. forward에서는 전체적(추론, bound, 검증)으로 graph 단일 적용이 우수하고 infer_s에서 약 20초 차이가 나며, backward에서는 total 시간이 비슷해지는 이유가 infer에서 깎인 약 20초를 bound에서 graph보다 약 20초 빨리 수행하기 때문이라고 서술되며, 위 이유로 일단 유지하기로 했다고 기록되어 있으나, 이는 실행 결과 해석·판단의 서술이지 구성 요소 간 상호작용의 측정 구조 자체를 직접 기술한 것은 아니다.
