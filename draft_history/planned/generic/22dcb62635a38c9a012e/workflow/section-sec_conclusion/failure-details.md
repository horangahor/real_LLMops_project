# 작성 검토 실패: section-sec_conclusion

## 검토 지적

- [editorial; 처리 책임: editor] cudaHostRegister와 No Pinning의 Bound/Infer 단계별 역전 서술이 p5의 실시간성·지연 관점과 연결되지 않고 독립적으로 제시된다. p4의 단계별 시간 역전 설명이 p5의 '평균은 No-Pin이 빠르지만 실시간성은 Pinned가 유리'라는 결론으로 자연스럽게 이어지지 않는다.
  - 문단: sec_conclusion_p3; 근거: 미지정
  - 실제 본문: 메모리 전송 방식 비교에서는 cudaHostRegister와 No Pinning의 전체 실행 시간 차이가 787.88초 대 776.70초로 약 1.4%(약 11초)에 불과했고, 92만 번 루프 중 1회당 약 12μs 수준의 미세한 차이로 나타났다. Bound 단계(전체 85%)에서는 cudaHostRegister가 658.80초로 No Pinning의 663.17초보다 4.37초 더 빨랐으나, Infer 단계(전체 15%)에서는 cudaHostRegister가 127.18초로 No Pinning의 111.92초보다 15.26초 더 느려 데이터 전송 직후 동기화가 일어나는 구간에서 역전되었다. 이 역전 때문에 전체 평균 처리 속도에서는 No-Pin이 약 13초 빨랐지만, 실시간성 관점에서는 다른 해석이 필요하다. [근거:E00277,E00278]
- [editorial; 처리 책임: editor] p4의 Bound/Infer 역전 설명 없이 p5에서 바로 '평균 처리 속도에서는 No-Pin이 약 13초 빨랐지만 실시간성에서는 Pinned가 안정적'이라는 대비가 나와, 독자가 두 문단의 인과 관계를 파악하기 어렵다.
  - 문단: sec_conclusion_p4; 근거: 미지정
  - 실제 본문: 실시간성 관점에서는 Pinned Memory가 No-Pin보다 유리하다. Pinned Memory는 최대 지연 1.64ms, 지터 47μs로 안정적인 반면, No-Pin은 최대 지연이 8.8~11.6ms로 치명적이고 지터가 118μs로 불안정하다. 이 차이는 1KB 수준의 작은 데이터를 매 루프마다 전송할 때 Pinned가 매번 하드웨어 DMA 셋업을 수행해 총 소요 시간이 더 길게 나온 데 기인한다. 다만 pinned memory 입력층은 제거했고, Graph manager에는 필요에 따라 pinned memory를 선택 할당 가능하도록 남겨 두었다. 즉 평균 처리 속도에서는 No-Pin이 약 13초 빨랐지만, 최악 지연(WCET)과 지터 안정성에서는 Pinned Memory가 더 유리하다. [근거:E00292,E00293,E00294,E00301,E00321]
- [editorial; 처리 책임: editor] 싱글 스트림 antenna_lirpa의 cuBLAS Batched GEMM·텐서 코어 활용 서술과 멀티스트림 배칭(method A)의 SM 포화 한계 서술이 한 문단에 섞여 있어, '싱글 스트림 고속화'와 '멀티스트림 배칭의 한계'가 구분되지 않는다.
  - 문단: sec_conclusion_p5; 근거: 미지정
  - 실제 본문: 싱글 스트림으로 동작하는 antenna_lirpa는 cuBLAS Batched GEMM과 텐서 코어를 활용해 현재 C++ 멀티스트림(8분)보다 약 4배 빠르게 동작한다. 방법 A(Multi-Stream 배칭, 현재 구현)는 기존 단일 샘플 커널을 유지해 3.2배 가속(25분→8분)을 얻었으나, 스트림 수의 한계(SM 포화)로 7~8분이 한계선이다. 커널 감소 측면에서는 Forward에서 lower/upper matmul 2→1, lower/upper bias matvec 2→1, matrix scaling + vector affine 2→1로 method 0 기준 레이어당 8→5회, Backward에서 split_pos_neg + bias accumulation 2→1 및 레이어당 backward 단계 5→4회로 줄었고, method 1에서는 forward 쪽 relaxation/cache 통합까지 포함되어 총 15회 감소, Backward-only에서는 각 타깃 레이어의 weight/bias 초기 복사 2회 제거와 backward 단계의 split/bias kernel 통합으로 총 12회 감소했다. [근거:E00261,E00263,E00314]
- [editorial; 처리 책임: editor] 실행 시간 결과 나열이 조건 설명 없이 긴 목록으로만 제시된다. CPU ONLY, GPU 버전, GPU OPTIMIZED, HYBRID, HYBRID V2, mempool+warmup 등 단계별 조건이 결과값과 함께 정리되지 않아 p2·p3의 최적화 서사와 연결되지 않는다.
  - 문단: sec_conclusion_p7; 근거: 미지정
