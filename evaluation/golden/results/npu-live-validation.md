# NPU 골든 PDF 실제 파일 검증

## 결론

현재 분석 기능을 실제 API로 한 번 실행했다. 새 구조 JSON에는 원문의 번호 있는 장·절 14개가 모두 있고 번호·계층도 맞는다. 그러나 서론의 문단 주제를 실제 소제목처럼 4개 추가했다. 따라서 목차 누락은 이번 실행에서 관찰되지 않았지만, 원문에 없는 구조를 추가하는 오류가 남아 있다.

이전 저장 분석은 원문 14개 중 제목 정체성이 대응되는 항목이 6개였다. 이 차이는 이전 요약의 변환본과 현재 API 재실행 결과의 차이이며, 프롬프트나 파서를 수정한 효과를 측정한 A/B 실험은 아니다. 이번 API 실행에서는 기존 `paper_structure.py`의 모델 요청·프롬프트·본문 전달 방식을 변경하지 않았다.

## 실행 기록

- 원본: `AIComps2026_NPU_Benchmarking_1.1v.pdf`, 14페이지.
- 사용자에게 NPU PDF 원본과 추출 본문의 Upstage 외부 전송 동의를 받은 후 실행했다.
- 흐름: Document Parse → 본문 텍스트 → Solar 구조 분석 → 프로파일 스키마 검증 → 원문 기준표 평가.
- 실제 응답 모델: `document-parse-260930`, `solar-pro4-260806`.
- Document Parse와 Solar 요청 모두 HTTP 200으로 완료되었다. 소요 시간은 각각 약 9.4초, 25.5초다. 토큰·실행 설정과 원문 대조 진단은 `npu-live-run-metadata.json`에 저장했다.
- 기존 `paper_structure_analysis.json`과 논문 초안은 유지했다. 새 JSON은 `../predictions/npu-live.json`에 별도 저장했다.
- 기준표는 Codex가 원문 텍스트와 페이지 이미지로 작성했다. 사용자·전문가의 독립 검수 전이며, 한 문서·한 번의 실행 결과다.

## 원문에 없는 소제목 4개

새 JSON은 서론 아래에 다음 항목을 추가했다.

1. 연구 배경 및 문제 제기
2. 세 가지 실험 조건 정의
3. 연구 질문 및 주요 결과 요약
4. 논문 구성 안내

원문의 1~3페이지에는 해당 내용의 문단이 있지만 위 이름의 실제 소제목은 없다. 모델의 `analysis_notes`에도 일부 제목은 실제 소제목이 아니라 문단 주제를 정리한 것이라고 적혀 있다. 관찰된 목차와 문단 작성 가이드를 혼동한 결과이므로 네 항목을 목차 오탐으로 판정했다.

`References`와 관련 연구의 실제 굵은 문단 소제목 3개는 원문에 존재한다. 처음부터 평가 범위에서 제외한 종류이므로 가상의 소제목과 구분해 제외했다.

## 파서 원본에서 확인한 내용

- 원문 목차 제목 텍스트는 14/14개가 추출 본문에 존재하고, 해당 페이지의 요소 텍스트에서도 확인됐다.
- 그중 heading 범주로 분류된 제목은 8/14개다. 서론·결과의 연구 질문 절·한계·결론 등은 텍스트에 있지만 heading 태그가 없었다. 페이지 머리말이나 일부 본문을 heading으로 분류한 사례도 있었다.
- 이는 목차 텍스트 보존과 레이아웃 분류의 차이를 보여준다. 전체 글자의 OCR 정확도·표 정확도·읽기 순서를 모두 측정한 점수는 아니다.
- 현재 분석 함수는 파서의 본문 텍스트만 Solar에 전달한다. 파서 응답에는 페이지 정보가 있으나 최종 프로파일의 모든 `source_pages`는 null이다. 페이지 연결은 파이프라인 차원의 보완 항목이다.

## 평가기 v2 수정 사항

첫 v1 채점은 참고문헌과 실제 굵은 문단 소제목을 제외한다고 명시했으면서 코드에서는 제외하지 않아, 위 4개도 오탐으로 계산했다. 당시 전체 출력 22개 기준 F1은 77.8%였다. 이 제외 범위 적용 오류를 v2에서 수정했다.

v2는 원문에서 확인된 해당 네 제목만 별도 기록하고, 가상의 서론 소제목 네 개는 오탐으로 유지한다. 따라서 평가 대상 18개 중 올바른 목차 14개로 정밀도 77.8%, 재현율 100.0%, F1 87.5%다. 기존 저장 분석도 같은 v2로 재채점했으며 기존 F1 60%/40%는 변하지 않았다. 파이프라인 출력 자체는 이 수정 과정에서 바꾸지 않았다.

## 재현

새 API 호출 없이 저장한 실제 출력만 다시 평가:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B golden_evaluation.py --profiles evaluation/golden/predictions/npu-live.json --output evaluation/golden/results/npu-live.json
```

항목별 비교와 각 파일 해시는 `npu-live.json` / `npu-live.md`에 있다. 전체 응답·원문 본문을 보존한 로컬 경로는 `draft_history/20261029-npu-live-validation/`이다. API 키나 인증 헤더는 기록하지 않았다.

## 다음 개선 대상

실제 제목만 `observed_outline`에 넣고 문단 주제·작성 계획은 `section_guidelines`로 분리하도록 분석 지침을 강화하고, 원문 페이지 정보를 유지하는 입력을 비교할 수 있다. 이는 아직 실행하지 않은 개선 과제다. 초안에 골든 구조·작성 방식이 반영되는 정도도 별도 평가가 필요하다.
