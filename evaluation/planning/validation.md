# 연구별 작성 계획·초안 실행 검증

같은 generic 프로젝트 설정과 같은 코드에 서로 다른 연구 PDF를 입력했다. 기존 CUDA 고정 작성기와 저장 초안은 변경하지 않았다.
입력 연구와 다른 논문의 가이드만 교차 연결했다. 원문 Parse 캐시를 재사용했고, 현재 코드로 네트워크를 금지한 전체 재생도 통과했다.

| 연구 입력 | 참고 가이드 | 근거 수 | 생성 장 수 | 필수 내용 충족 (LLM 보조) | 참고 적용 (LLM 보조) | 로컬 검증 |
|---|---|---:|---:|---:|---|---|
| NPU | RGBD | 18 | 6 | 27/27 | 적용 6, 부분 0, 미확인 0 | 통과 |
| RGBD | NPU | 18 | 5 | 30/30 | 적용 4, 부분 1, 미확인 0 | 통과 |

## NPU 계획

제목: 벤더 가이드 최적화가 엣지 NPU 성능에 미치는 영향: 모델 변환과 배포 파이프라인의 분리 평가

[계획 JSON](examples/npu-plan.json) · [생성 초안](examples/npu-draft.md) · [검토 기록](examples/npu-review.json)

| 장 | 역할 | 소절 수 | 참고 구성 적용 계획 |
|---|---|---:|---|
| 서론 | introduction | 3 | ref1_introduction의 구성 방식(연구 배경→기존 방법 대비→제안 목표 목록)을 따르되, 이 연구에서는 모델 융합이나 다중 모달 논의가 아니라 벤더 가이드 최적화의 효과를 NPU 수준/배포 수준으로 분리하는 데 초점을 맞춘다. 따라서 기존 방법의 계열별 대비는 벤더 가이드 최적화 적용 범위(모델 변환만 vs 배포 파이프라인 전체)로 재해석해 서술한다. |
| 연구 설계 | methods | 5 | ref1_methods의 단계적 서술 방식(조건 통제→환경/대상→구성 요소→설정)을 따르되, 이 연구에서는 모델 구조나 학습 설정보다 실험 조건 세 가지와 각 구성의 보존/변경 범위를 명확히 구분하는 데 중점을 둔다. 특히 Baseline 대비 VG-NPU가 무엇을 보존하고 VG-E2E가 무엇을 추가로 적용하는지를 설계 차원에서 분리해 제시한다. |
| 벤더 가이드 최적화의 효과 분석 | evaluation | 3 | ref1_evaluation의 비교·해석 중심 전개(지표 비교→차이 원인 해석→배포 가능성 논의)를 따르되, 이 연구에서는 모델 구조 변형이나 제거 실험이 아니라 구성 조건 간 비교에 초점을 둔다. 따라서 성능 비교는 VG-NPU와 VG-E2E를 각각 Baseline 대비로 해석하고, 지연 감소가 정확도 보존을 보장하지 않는다는 점을 결과 해석의 중심에 둔다. |
| NPU 수준과 엔드투엔드 성능 순위의 관계 | evaluation | 2 | ref1_evaluation의 해석 중심 전개를 재사용하되, 이 절은 모델 변형 비교가 아니라 동일 호스트에서 관찰된 NPU 간 상대 순위 변화와 그 일반화의 한계를 다룬다. 따라서 시각 해석 자료나 제거 실험 대신, 워크로드별 순위 변화 여부와 NPU-only 성능의 예측 한계를 중심으로 서술한다. |
| 한계 및 향후 연구 | limitations | 3 | ref1_limitations의 서술 순서(유효 범위 인정→제약 지적→개선 방향 정리)를 따르되, 이 연구에서는 데이터 다양성보다 평가 대상 NPU·워크로드 범위와 구성 분리의 해석상 제약을 중심으로 서술한다. 특히 VG-E2E의 추가 이득이 단일 요소로 귀속되지 않는다는 점과 NPU-only 성능의 예측 한계가 일반화 주장에 제약을 준다는 점을 명시한다. |
| 결론 | conclusion | 3 | ref1_conclusion의 짧은 종합 방식(문제·방법 재진술→핵심 결과→실용적 의미)을 따르되, 이 연구에서는 모델 구조나 융합 전략이 아니라 벤더 가이드 최적화를 모델 변환 수준과 배포 수준으로 분리한 벤치마킹 방법론과 그 결과를 중심으로 정리한다. |

| 장 | 역할 | 소절 수 | 참고 구성 적용 계획 |
|---|---|---:|---|
| 서론 | introduction | 5 | ref1_introduction의 문단 전개(영역 중요성→비교 어려움→연구 공백→조건 정의→결과 요약→구성 안내)를 따르되, 본 연구는 벤치마킹·시스템 오버헤드 문헌이 아니라 단일 프레임워크 제안 논문이므로 ‘비교의 어려움’을 RGB-only 대비 RGBD 융합, 정확도·FPS 동시 고려, 이식 제어 파이프라인 통합 맥락으로 좁혀 서술한다. |
| 방법 | methods | 5 | ref1_methods의 문단 전개(구성/조건 정의→실행 경로·측정 구간→공통 고정 요소→워크로드·데이터셋→환경별 설정→플랫폼·스택)를 따르되, 본 연구는 ‘실행 경로·측정 구간’을 추론 FPS 측정 조건(Jetson AGX Xavier, PyTorch FP32, batch 1, 100장 평균, 전처리·병렬 제어 스레드 포함)으로 구체화하고, 모델 구조 표는 RGB-CTA / RGBD-CTA-D / RGBD-CTA-F의 차이를 기준선·변경 범위·측정 초점 관점에서 정리한다. |
| 평가 | evaluation | 5 | ref1_evaluation의 문단 전개(평가 대상·표 안내→질문별 결과→구성 간 차이·순위 변화→추가 이득 크기·동시 변경 제약)를 따르되, 본 연구는 단일 테이블(모델별 정확도·정밀도·재현율·F1·Params·GFLOPs·FPS)을 기준선으로 먼저 제시하고, 본문에서는 RGBD-CTA-F의 +4.9% ablation, 파라미터·GFLOPs·FPS 증가, 이식 파이프라인 통합 시 5.2 FPS 유지 등 차이점과 예외만 서술한다. |
| 한계 | limitations | 5 | ref1_limitations의 문단 전개(범위·조건→제한한 최적화 사유→동시 변경→호스트 차이→제외 지표→적용 범위)를 따르되, 본 연구는 전력·에너지 효율 평가가 자료에 없으므로 해당 항목을 ‘제외된 평가’로 명시하고, FPS가 특정 edge 장치·PyTorch FP32·batch 1·100장 평균·전처리·병렬 제어 스레드 포함 조건에서 측정된 점을 해석 제약으로 밝힌다. |
| 결론 | conclusion | 4 | ref1_conclusion의 문단 전개(범위·접근 재제시→수준별 발견 정리→순위 변화·추가 이득·정확도 보존→비교 고려 요소→확장 방향)를 따르되, 본 연구는 ‘수준별’을 (1) RGBD 융합 효과, (2) 모델 변형 간 정확도·복잡도·속도, (3) 이식 파이프라인 통합 실시간성으로 구분해 정리한다. |

## 결과의 의미와 한계

- 일반 연구 입력은 optimization_methods 목록이나 CUDA/CROWN 전용 장 제목을 요구하지 않는다. 장 수·소절·필수 내용·근거·참고 적용 방식이 계획으로 전달된다.
- 완료까지 출력 스키마·근거 연결·검토 프로토콜을 개선하고 제한된 수정/재시도를 수행했다. 첫 시도 성공률·처리 속도·비용의 통제 실험이 아니다.
- source_quote_links_checked는 인용 문자열이 실제 원문 요소와 페이지에 존재한다는 검사다. 추출 주장의 의미·수치 해석·인과의 정확성 점수가 아니다.
- 필수 내용과 참고 적용 수치는 LLM 보조 판정이다. 문단 ID의 존재를 코드로 확인하지만 그 문단이 항목을 충분히 설명하는지는 별도 사람 검수가 필요하다.
- 새 과학적 성과를 만든 것이 아니라 이미 제공된 두 논문을 연구 입력으로 재구성한 개발 실행 검증이다. 독립 보류 평가셋의 일반화 성능이 아니다.
- 원본 행·열이 제공되지 않은 표는 모델이 만들어 배치할 수 없다. PDF 표의 자동 행·열 구조화는 추가 구현 대상이며 수작업 표로 대체하지 않는다.
- CUDA 수작업 근거는 과거 기록으로 보존하며 현재 실행 경로에서 로드하지 않는다. CUDA 프로젝트도 input/ 원본 PDF에서 자동 추출한다.

## 재생 검증

```powershell
python -X utf8 -B evaluation/planning/summarize_runs.py
```

ignored 실행 폴더가 필요하다. 다른 PC에서 실제 모델을 다시 실행하려면 새 출력 폴더를 지정한다. 원문 PDF와 API 설정은 별도로 준비한다.
