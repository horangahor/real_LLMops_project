# input 폴더 CUDA 연구 입력 실행 검증

[생성 초안](examples/cuda-input-draft.md) · [작성 계획](examples/cuda-input-plan.json) · [자동 검토](examples/cuda-input-review.json)

## 입력 및 실행

- 입력: `input/GPU 프로그래밍의 핵심_ CUDA로 배우는 병렬 처리 기술.pdf`. Document Parse가 84쪽, 651개 요소를 반환했다.
- 파일명이 같은 이전 검토 원본과 SHA-256이 다르다. 기존 수작업 CUDA 근거를 재사용하거나 해시를 바꾸지 않았다.
- Studio를 거치지 않고 Document Parse API → Solar 구간별 근거 추출 → 일반 연구 계획·작성·검토 경로로 실행했다.
- 20쪽 단위 5개 구간에서 후보를 추출해 근거 17개를 선택했다. 모든 구간의 후보가 최종 선택에 포함됐다.
- 선택한 원문 요소에서 코드가 직접 연결한 인용문·페이지 39곳과 입력 해시를 재검사했다.
- 앱과 같은 PaperDraftOrchestrator의 adaptive/generic 경로를 네트워크 금지 상태로 재실행해 캐시 재생을 확인했다. 입력 원본 파일은 유지한다.

## 자동 검토와 한계

- 근거가 배정된 필수 항목: 28/28. 참고 구성: 적용 12, 부분 적용 2. 모두 LLM 보조 판정이다.
- 근거가 없는 미래 과제·미해결 항목 2개는 met 판정을 needs_check로 낮추고 충족률 계산에서 제외했다.
- 자동 검토 오류 0개, 경고 18개. 탐지된 오류가 없다는 것은 독립적으로 사실 정확성을 입증한 결과가 아니다.
- 반복 문단과 장 사이의 역할 중복, 긴 미해결 항목 목록에 대한 경고가 남았다. 투고 가능한 완성본으로 평가하지 않는다.
- 선택된 근거는 요약이며 84쪽의 모든 실험·로그·표를 완전히 추출한 것이 아니다. 원문 요소 선택이 맞아도 주장의 해석은 저자 확인이 필요하다.
- 이번 실행 중 긴 자료의 앞부분 편중·인용 문자열 불일치와 잘린 검토 JSON을 발견해 구간별 추출·원문 ID 연결·제한된 JSON 재시도를 보완했다. 최초 시도 성공률·비용·속도를 통제한 평가가 아니다.
- 새 PDF의 표를 모델이 임의로 새로 만들도록 허용하지 않았다. PDF 표의 자동 행·열 구조화는 추가 구현 대상이며 수작업 표를 대신 삽입하지 않는다.
- 코드 회귀 테스트 115개 통과. 기존 CUDA 비교 경로에서도 수작업 근거를 자동 삽입하는 연결을 제거했다. CUDA 프로젝트도 원본 PDF에서 자동 추출한다.

## 앱에서 사용

기본 작성 방식에서 **input 폴더의 연구 자료**를 선택한다. **작성 계획만 만들기** 또는 **논문 초안 작성 시작**을 누르면 입력이 같은 완료 단계는 캐시로 불러온다.

```powershell
python -m streamlit run streamlit_app.py
```

수작업 파일 읽기와 네트워크를 모두 차단한 기본 API 재생도 통과했다. 근거 17개와 저장 초안은 동일하다. [검증 기록](automatic-evidence-validation.json).
