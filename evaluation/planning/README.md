# 연구별 작성 계획·초안 평가

이 경로는 참고 논문의 목차 추출 F1과 별개다. 연구 자료를 바꿔도 같은 프로그램이 적절한 계획과 초안을 만드는지 확인한다.

## 자동 검증 및 진단 지표

| 항목 | 정의 | 해석 범위 |
|---|---|---|
| 계획 유효성 | 실제 연구 ID·참고 ID·표 ID, 장 역할, 작성 의존 관계, 프로젝트 정책 검사 | 코드의 구조·연결 검사 |
| 장·소절 준수 | 계획의 본문 칸을 모델이 채우고 코드가 제목·번호를 조립 | 목차 형식 검사, 전개의 의미적 품질은 별도 |
| 입력 근거 배정 | 계획에 배정된 서로 다른 근거 수 / 입력 근거 수 | 배정 현황이며 무조건 높아야 하는 품질 점수는 아님 |
| 필수 내용 충족률 | 검토에서 met으로 판정하고 실제 초안 문단 ID와 요구 근거가 확인된 항목 / 근거가 있는 계획 필수 항목 | LLM 보조 판정. 계획 자체가 빠뜨린 항목은 이 분모에 없으므로 외부 기준과 함께 평가 |
| 참고 가이드 연결 | 같은 역할의 가이드가 있는 작성 장 중 가이드 ID·적용 설명을 가진 장 수 | 계획 단계의 연결 검사, 본문 반영률과 구분 |
| 참고 구성 본문 적용 | 장별로 선택한 가이드를 applied/partial/not_visible로 분류하고 본문 인용·이유 기록 | LLM 보조 검토. 모든 선택 가이드를 한 번씩 검토해야 통과 |
| 근거 ID 검사 | 장 본문의 인용이 해당 장에 허용된 연구 ID인지 확인 | ID가 맞아도 주장의 의미가 참이라는 뜻은 아님 |
| 품질 게이트 | 사실 오류·근거 없는 주장·필수 항목 오류가 남으면 후보 보존 | 오류 탐지는 LLM 판단과 로컬 검사를 결합, 독립 검증 아님 |

검토자는 초안 문단 ID를 선택하고 코드는 그 문단의 실제 텍스트를 인용으로 연결한다. 원문 문장을 초안 인용인 것처럼 보고하는 오류를 막는다.
문단이 존재한다는 확인과 그 문단이 사실을 올바르게 설명했다는 의미적 판정은 구분한다.
근거가 배정되지 않은 항목을 검토자가 met으로 판정해도 코드는 needs_check로 낮추고, 근거 기반 충족률의 분모·분자에서 제외한다.

골든 샘플의 원문 제목·성능 수치·목차는 작성자에게 연구 사실로 전달하지 않는다. 계획자는 역할 계층과 재사용 가이드를 참고하고,
작성자는 자신에게 선택된 지침·목적·필수 내용·연구 근거만 받는다. 앞 장은 목적·구성만 문맥으로 받아 실험 이력의 반복 유입을 줄인다.

## 사람 검수용 공통 기준

연구별 필수 사실과 해석 한계를 초안을 보기 전에 고정한다. 사실·수치 주장을 가능한 한 원자적으로 나누고 근거 대조 결과와 분모를 기록한다.
평가기준을 만든 연구와 개발에 사용하지 않은 연구를 구분한다. 같은 모델의 Reviewer 승인율을 사실 정확도로 보고하지 않는다.

1. 사실 정확성: 검토 대상 주장 중 원문이 같은 조건·대상·단위·해석 강도로 뒷받침하는 주장 수와 비율.
2. 핵심 내용 충족: 사전에 고정한 필수 문제·방법·조건·결과·한계 중 올바르게 설명한 항목 수와 비율.
3. 참고 내용 혼입: 다른 논문의 장비·실험·수치·성과를 이번 연구 사실로 쓴 오류 수와 근거 문장.
4. 구성 반영: 선택한 문단 전개·설계 이유 설명·비교 조건 제시 방식이 실제로 보이는지 문단을 인용해 0(없음)/1(부분)/2(명확)로 판정.
5. 읽기 품질: 중복·장 역할 혼재·근거 없는 과장·논리 연결 문제를 고정 기준으로 판정. 글자 수나 숫자 개수로 대체하지 않는다.

## 실행 검증

`tests/test_planned_paper.py`는 서로 다른 주제에서 장 수가 달라지는 경우, 빈 관련 연구 정책, 잘못된 ID·순환 의존·누락 항목,
본문 인용 위조, 참고 가이드 미검토, 실패 시 기존 초안 보존, 무통신 캐시 재사용을 검증한다.

실제 API 검증 원본은 ignored `draft_history/planned-validation/`에 보관한다. NPU와 RGBD 논문은 개발·실행 확인용 자료다.
두 논문을 입력 연구로 각각 사용하고 다른 논문의 가이드만 참고하도록 교차 연결한다. 이미 사용한 공개 논문을 재구성한 기능 검증이며 새 연구 성과가 아니다.
이 실행으로 다른 모든 연구에서의 정확도나 문체 품질을 주장하지 않는다. 실행 결과는 검증 완료 후 `validation.md`에 기록한다.

추가된 84쪽 CUDA 연구노트의 일반 입력 실행은 [input CUDA 검증 보고서](input-cuda-validation.md)에 분리했다. 긴 자료의 구간별 근거 선택·원문 ID 연결·앱 경로 재생을 확인했으며, 이전 CUDA 검토 근거를 재사용한 결과가 아니다.
