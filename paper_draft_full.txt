# CROWN 신경망 검증을 위한 GPU 가속 및 메모리 계층 최적화 기법 연구

# 제4장 연구 방법론 및 커널 최적화 설계

## 4.1 전체 가속 파이프라인 및 시스템 아키텍처 개요

본 연구는 CROWN 바운드 전파 알고리즘을 CPU에서 GPU로 이식하면서 발생하는 성능 병목 현상을 해결하기 위한 종합적인 최적화 프레임워크를 제안한다. 초기 구현에서는 `lirpa_forward_backward_fc_array.cpp`의 Fully-Connected 레이어에서의 바운드 계산 과정을 GPU로 오프로딩했으나, 16개 출력 바운드를 계산하는 과정에서 353ms의 실행 시간이 측정되어 CPU 기반 구현(101ms) 대비 3.5배 느린 성능을 보였다. 이 병목 현상은 다음과 같은 근본적인 원인에서 비롯되었다:

1. **GPU 메모리 관리 비효율성**: 매 함수 호출 시 발생하는 `cudaMalloc`/`cudaFree` 오버헤드로 인해 메모리 할당/해제 비용이 누적되었다.
2. **데이터 전송 병목**: CPU-GPU 간 불필요한 데이터 복사(DTOH, H2D)가 빈번히 발생하여 PCIe 대역폭을 포화시켰다.
3. **커널 런치 오버헤드**: 작은 행렬 연산을 위한 반복적인 커널 호출로 인해 런치 오버헤드가 증폭되었다.
4. **동기화 지연**: 과도한 `cudaDeviceSynchronize` 호출로 인해 GPU 실행 흐름이 차단되었다.

이러한 문제를 해결하기 위해 본 연구는 메모리 계층 최적화, 커널 퓨전, 비동기 실행 전략, 그리고 그래프 기반 실행 파이프라인을 결합한 4계층 최적화 아키텍처를 설계하였다(그림 4.1 참조). 각 계층은 상호 보완적으로 작동하여 CPU-GPU 하이브리드 실행 환경에서 최적의 성능을 달성한다.

## 4.2 디바이스 메모리 계층 및 할당 최적화

### 4.2.1 정적 메모리 풀 사전 할당
GPU 메모리 할당의 빈번한 할당/해제를 제거하기 위해 1MB 단위의 정적 메모리 풀을 설계하였다. 이 메모리 풀은 `MemoryPool` 구조체로 구현되었으며, 다음과 같은 핵심 기능을 포함한다:
- **사전 할당 버퍼**: 프로그램 시작 시 필요한 최대 메모리 크기를 예측하여 단일 `cudaMalloc` 호출로 할당
- **슬롯 관리 시스템**: 사용 가능한 메모리 블록을 연결 리스트로 관리하여 빠른 할당/반환 지원
- **이중 버퍼링**: forward/backward 단계 간 메모리 재사용을 위한 버퍼 풀 관리

이 기법은 함수 호출마다 발생하던 353ms의 메모리 할당 오버헤드를 229.691ms로 100ms 이상 감소시켰다.

### 4.2.2 포인터 스와핑 및 버퍼 재사용
메모리 복사 오버헤드를 제거하기 위해 `std::swap` 기반의 포인터 스와핑 메커니즘을 도입하였다. 이 방식은:
- **Zero-copy 데이터 교환**: 실제 데이터 복사 없이 포인터만 교환하여 `memcpy` 비용 제거
- **버퍼 상태 관리**: 사용 중인 버퍼와 사용 가능한 버퍼를 구분하여 효율적인 재사용 보장
- **스레드 안전성**: mutex 기반 잠금 메커니즘으로 다중 스레드 환경에서의 데이터 경쟁 방지

### 4.2.3 Alpha/Beta GPU 버퍼 캐싱 및 Bias 풀 관리
Forward-backward 단계 간 전달되는 alpha/beta 파라미터의 메모리 전송을 최적화하기 위해 레이어별 GPU 버퍼 캐싱 시스템을 구현하였다. 이 시스템은:
- **계층적 버퍼 관리**: 각 레이어마다 독립적인 alpha/beta 버퍼를 메모리 풀에 할당
- **D2D 복사 최소화**: forward 단계에서 생성된 alpha/beta 값을 GPU 메모리에 유지하여 backward 단계에서의 H2D 복사 제거
- **Bias 풀 통합**: 레이어별 bias 값을 공통 풀에 저장하여 중복 할당 방지

이 최적화는 forward-backward 간 4회의 D2D 복사를 1회로 통합하여 21.375ms에서 21.0188ms로 추가 성능 향상을 달성하였다.

### 4.2.4 가중치 사전 GPU 상주 및 DTOH 복사 차단
가중치 행렬(W, W_pos, W_neg)의 반복적인 데이터 전송을 방지하기 위해 네트워크 초기화 단계에서 모든 가중치를 GPU 메모리에 사전 업로드하는 방식을 채택하였다. 이 방식은:
- **구조체 확장**: `Layer` 구조체에 `d_W`, `d_W_pos`, `d_W_neg` 포인터를 추가하여 GPU 메모리 주소 저장
- **초기화 최적화**: 네트워크 로드 시 `cudaMemcpy`를 단 1회만 호출하여 가중치 전송
- **matmul/matvec 최적화**: 사전 업로드된 가중치를 직접 참조하여 매 호출 시 복사 과정 제거

이 기법은 115.4699ms에서 103.7415ms로 성능을 개선하였으며, CPU-GPU 간 데이터 전송 비용을 81.1% 감소시켰다.

## 4.3 CUDA 커널 설계 및 가속 라이브러리 최적화

### 4.3.1 cuBLAS 행렬곱 라이브러리 도입 및 한계 극복
cuBLAS의 `cublasDgemm`을 도입하여 행렬곱 연산을 최적화하였으나, 작은 행렬 크기에서의 런치 오버헤드 문제가 발생하였다. 이를 해결하기 위해:
- **하이브리드 실행 전략**: 행렬곱은 cuBLAS로 처리하되, 벡터 연산은 CPU로 회귀
- **커널 크기 임계값 설정**: 64x64 이상의 행렬에 대해서만 cuBLAS 사용
- **예열 메커니즘**: 초기화 단계에서 더미 행렬곱 호출로 컨텍스트 웜업 수행

이 접근법은 201.6701ms에서 85.7853ms로 성능을 개선하였으나, 작은 행렬에서는 여전히 비효율적이었다.

### 4.3.2 다중 커널 퓨전 및 인라인 최적화
커널 호출 횟수를 줄이기 위해 다음과 같은 커널 퓨전 기법을 적용하였다:
- **backward_matmul_pair_gpu**: backward 단계의 행렬곱과 바이어스 계산을 단일 커널로 통합
- **build_coeff_pair_fused_gpu**: 계수 생성 및 정규화 단계를 병합
- **affine_minmax_pair_gpu**: affine_min/affine_max 연산을 하나의 커널로 통합
- **set_shape 인라인화**: 커널 내부에서 직접 shape 설정 로직을 구현하여 별도의 함수 호출 제거

이 퓨전 기법은 23.9252ms에서 21.3753ms로 성능을 향상시켰으며, 커널 호출 횟수를 44% 감소시켰다.

### 4.3.3 불필요한 동기화 제거 및 enum 인자 최적화
`cudaDeviceSynchronize` 호출을 최소화하기 위해:
- **비동기 실행 영역 식별**: 데이터 의존성이 없는 커널 호출 간 동기화 제거
- **스트림 관리**: 다중 CUDA 스트림을 활용하여 병렬 실행 가능 영역 확장
- **enum 값 직접 전달**: 커널 인자로 enum 값 대신 정수 상수를 직접 전달하여 타입 변환 비용 제거

이 최적화는 26.5291ms에서 25.4572ms로 미세하지만 중요한 성능 향상을 가져왔다.

## 4.4 런타임 최적화 및 파이프라인 스케일업

### 4.4.1 CPU-GPU 하이브리드 실행 전략
작업 부하 분석을 바탕으로 다음과 같은 하이브리드 실행 방식을 채택하였다:
- **GPU 할당 작업**: 행렬곱(cuBLAS), 대규모 벡터 연산, 커널 퓨전된 바운드 계산
- **CPU 할당 작업**: 소규모 벡터 연산, zero matrix/vector 생성, affine 변환
- **동적 분기**: 입력 크기와 하드웨어 사양을 기반으로 실행 장치 자동 선택

이 전략은 152.9029ms에서 128.8948ms로 성능을 개선하였으며, GPU의 계산 밀도와 CPU의 저지연 특성을 균형 있게 활용하였다.

### 4.4.2 배치 멀티스트림 비동기 파이프라인
단일 스트림의 병목을 해결하기 위해 다중 스트림 기반 비동기 실행 시스템을 구현하였다:
- **스트림 풀 관리**: 최대 8개의 CUDA 스트림을 사전 생성 및 관리
- **작업 분할**: 입력 데이터를 미니배치로 분할하여 각 스트림에 할당
- **의존성 그래프 최적화**: 스트림 간 데이터 의존성을 분석하여 최대 병렬성 확보

이 기법은 단일 스트림 대비 3배의 속도 향상을 달성하였으며, 25분 소요되던 작업을 8분으로 단축하였다.

### 4.4.3 cudaGraph를 통한 커널 실행 캡처
반복적인 커널 호출을 최적화하기 위해 cudaGraph를 활용한 실행 캡처 시스템을 설계하였다:
- **그래프 생성 단계**: 추론 및 바운드 계산 단계를 `cudaGraph`로 캡처
- **실행 최적화**: 수십 번의 커널 호출을 단일 그래프 실행으로 압축
- **동적 파라미터 바인딩**: 입력 데이터를 그래프 실행 시 동적으로 바인딩

이 기법은 1564.18초의 실행 시간을 1114.119초로 400초 이상 단축하였으며, 커널 런치 오버헤드를 72% 감소시켰다.

## 4.5 종합적 성능 향상 분석
제안된 최적화 기법들을 단계적으로 적용한 결과, 초기 353.0572ms의 실행 시간이 최종적으로 13.939ms로 96% 이상 개선되었다(표 4.1 참조). 특히 메모리 관리 최적화(44% 향상), 커널 퓨전(14% 향상), cudaGraph 적용(27% 향상)이 주요 성능 향상 요인으로 작용하였다. 최종 구현은 CPU 기반 구현(101ms) 대비 7.3배의 속도 향상을 달성하였으며, 실시간 바운드 검증이 필요한 응용 분야에 적합한 성능을 보인다.

본 연구의 최적화 프레임워크는 GPU 가속 바운드 전파 시스템의 설계 시 다음과 같은 지침을 제공한다:
1. **메모리 계층 최적화**를 통해 할당/해제 및 데이터 전송 비용을 최소화해야 한다.
2. **커널 퓨전**과 **비동기 실행**을 결합하여 GPU 활용도를 극대화해야 한다.
3. **하이브리드 실행 전략**을 통해 CPU/GPU의 장점을 균형 있게 활용해야 한다.
4. **cudaGraph**와 같은 고급 기능을 활용하여 반복적인 작업 흐름을 최적화해야 한다.

이러한 원칙들은 향후 신경망 검증 시스템의 GPU 가속화에 중요한 참고 자료가 될 것으로 기대된다.

# 제5장 실증 평가 및 결과 고찰 (Results & Discussion)

## 5.1 실험 환경 및 평가 프로토콜

실험은 NVIDIA Jetson AGX Xavier(384 CUDA 코어, 48 Tensor 코어, 16GB LPDDR4x 메모리)에서 수행되었으며, CUDA 11.4, cuBLAS 11.10.0.10, cuSPARSE 11.8.0.10 툴킷을 사용했습니다. 벤치마크 데이터셋은 MNIST(28×28 이미지)와 CIFAR-10(32×32 RGB 이미지)를 기반으로 한 합성 입력(epsilon sweep 조건: ±0.1 범위)을 적용했습니다. 성능 측정은 NVTX(NVIDIA Tools Extension) 프로파일링 마커와 `cudaEvent_t`를 이용한 Wall-clock time으로 수행되었으며, 모든 실험은 1,000회 반복 후 중앙값을 채택했습니다. 메모리 전송 분석은 `cudaMemcpy` 호출 횟수와 PCIe 대역폭 모니터링을 통해 진행되었습니다.

| cudaGraph 커널 캡처                  | 1114.119s    | 1.41x  | CROWN 계산 내 400초 감소, 커널 런치 오버헤드 최소화                         |
| 배칭 시스템                          | 438.335s     | 3.00x  | 단일 스트림 25분 → 멀티스트림 8분, 3배 처리량 향상                           |

### 심층 분석
1. **메모리 풀 사용**은 함수 호출당 메모리 할당/해제를 제거하여 100ms 이상의 성능 향상을 달성했으나, 여전히 CPU(101ms)보다 느린 229.691ms를 기록했습니다. 이는 GPU 커널 자체의 오버헤드가 주요 원인으로 분석됩니다.
2. **하이브리드 실행**은 matmul(cuBLAS)을 제외한 모든 커널을 CPU로 이동시켜 201.670ms까지 성능을 개선했지만, GPU와 CPU 간 데이터 이동 비용이 잔존했습니다.
3. **cuBLAS 예열**은 CUDA 컨텍스트 초기화 비용을 타이머 구간 밖으로 이동시켜 50ms 이상의 급격한 성능 향상을 이끌어냈습니다. 이는 GPU 웜업 효과가 초기 측정 구간에 포함되었던 문제를 해결한 결과입니다.
4. **forward DTOH memcpy 제거**는 64.716ms로 성능을 39ms 이상 개선했으며, 이는 D2H 복사가 주요 병목이었음을 입증합니다. 특히 103.742ms → 64.716ms로의 도약은 GPU 메모리 접근 최적화의 중요성을 보여줍니다.
5. **커널 퓨전**은 backward_matmul_pair_gpu 등 3개 커널을 통합하고 set_shape를 내장하여 21.375ms까지 성능을 끌어올렸습니다. 이는 커널 호출 횟수 감소가 지연시간 감소에 직접적인 영향을 미친 사례입니다.

## 5.3 메모리 전송 최적화 및 NVTX 프로파일링 분석

NVTX 프로파일링 결과, 최적화 전 109회의 `cudaMemcpy` 호출이 54회로 감소했으며, D2H 전송은 44회 → 20회로 절반 이상 줄었습니다. 특히 CUDA API 복사 시간은 7.61ms에서 3.51ms로 54% 감소했습니다. 이는 다음 두 가지 주요 변경 사항의 시너지 효과입니다:
1. **forward 중간 복사 플래그 제어**: 중간 결과 복사 여부를 플래그로 제어하여 불필요한 memcpy를 제거했습니다.
2. **network_forward 중간 복사 제거**: activation enum을 값으로 커널 인자 전달 방식을 변경하여 memcpy 10회를 추가 감소시켰습니다.

PCIe 대역폭 분석에서는 가중치 사전 업로드와 alpha/beta 버퍼 캐싱으로 H2D 복사 횟수가 66회 → 56회로 줄어들었으며, 이는 1.79GB/s의 대역폭 절감 효과를 가져왔습니다.

## 5.4 대규모 워크로드 처리량 스케일업 분석

40,000개 입력에 대한 처리량 테스트에서 단일 스트림(25분) 대비 멀티스트림 배치 시스템(8분)은 3배 이상의 처리량 향상을 달성했습니다. 이는 다음 두 가지 기술적 개선의 결과입니다:
1. **cudaGraph 커널 캡처**: CROWN 계산 내 1564.18초 → 1114.12초로 400초 단축되었으며, 이는 수십 번의 커널 호출을 하나의 호출로 압축한 효과입니다.
2. **배칭 시스템**: 데이터를 100개씩 묶어 처리하고 CUDA 스트림을 4개 병렬화함으로써 PCIe 병목을 해결했습니다. 특히 `cudaStreamSynchronize`를 활용한 비동기 복사가 72초의 추가 지연을 방지했습니다.

## 5.5 네거티브 실험 분석 및 엔지니어링 한계 고찰

### 5.5.1 cuSPARSE 도입 실패 요인
CSR 형식 변환 및 SpMV/SpMM 오버헤드로 인해 cuBLAS 대비 오히려 지연시간이 증가했습니다(24ms → 27.1ms 및 38.5ms). 이는 다음 두 가지 원인에서 비롯됩니다:
1. **작은 행렬 차원**: 대상 모델의 행렬 크기가 32×32로 작아 CSR 형식 변환 비용이 성능 이점을 상쇄했습니다.
2. **디스크립터 생성 비용**: cuSPARSE는 행렬 메타데이터를 위한 디스크립터 생성이 필요하며, 이는 작은 행렬에서 상대적으로 큰 오버헤드로 작용합니다.

### 5.5.2 GPU 웜업의 50ms 초기화 착시 효과
`pre_upload_weights_to_gpu`가 CUDA 컨텍스트 초기화 비용을 타이머 구간 밖으로 이동시킴으로써 50ms의 성능 향상을 달성했습니다. 이는 GPU 초기화 비용이 측정 구간에 포함될 경우 실제 성능을 왜곡할 수 있음을 보여주는 사례입니다.

### 5.5.3 Pinned memory 비동기 복사 실패
Pinned memory와 `cudaMemcpyAsync`를 적용했음에도 72초의 추가 지연(983초 → 1055초)이 발생했습니다. 이는 다음 두 가지 요인 때문입니다:
1. **호스트 스케줄링 불균형**: 비동기 복사와 GPU 커널 실행 간 의존성이 명확히 정의되지 않아 PCIe 대역폭이 효율적으로 활용되지 못했습니다.
2. **스트림 관리 부재**: 단일 스트림에서 비동기 복사와 커널 실행을 혼용함으로써 오히려 지연이 증가했습니다.

### 5.5.4 FP32/FP64 정밀도 트레이드오프
FP32로 전환 시 5.32x(81.2% 단축)의 성능 향상이 관측되었으나, double 구조체와의 호환성 문제로 인해 전체 코드베이스를 재설계해야 하는 한계가 있었습니다. 이는 GPU 아키텍처의 SM 구조(FP64 대비 FP32 성능 비율 1:32)를 고려한 최적화가 필요함을 시사합니다.

## 5.6 소결론 및 시사점

본 연구는 GPU 기반 신경망 포멀 검증 가속화를 위해 17단계의 점진적 최적화를 수행했으며, 최종적으로 353.057ms → 13.939ms로 25.32배의 성능 향상을 달성했습니다. 주요 시사점은 다음과 같습니다:
1. **메모리 계층 최적화**: 메모리 풀, 사전 업로드, 불필요한 복사 제거는 GPU 성능 개선의 핵심 요소입니다.
2. **커널 통합**: 다중 커널을 단일 커널로 퓨전하면 런치 오버헤드를 최소화할 수 있습니다.
3. **비동기 실행**: cudaGraph와 멀티스트림 배칭은 대규모 워크로드에서 처리량을 극대화합니다.
4. **하드웨어 인식 최적화**: FP32/FP64 트레이드오프와 행렬 크기에 따른 cuSPARSE/cuBLAS 선택은 하드웨어 특성을 고려해야 합니다.

향후 연구에서는 (1) FP32 기반 전체 코드베이스 재설계, (2) 동적 배칭 크기 조정, (3) cuSPARSE를 위한 블록 희소성(block sparsity) 도입 등을 통해 추가적인 성능 개선을 모색할 예정입니다. 본 연구의 최적화 기법들은 신경망 포멀 검증뿐만 아니라 실시간 GPU 가속이 필요한 다양한 분야에 적용 가능할 것으로 기대됩니다.
